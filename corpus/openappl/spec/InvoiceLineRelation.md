# InvoiceLineRelation

**Level:** `subsection` · **Family:** [ObjectSettings](../ontology/families.md#objectsettings) (domain `DataObject`)

**Ontology:** [InvoiceLineRelation in Part 1](../ontology/InvoiceLineRelation.md)

How an invoicing-enabled object relates to its line item object (provider-neutral sibling of StripeOrderItemRelation). The line item object is the EDITABLE SOURCE of invoice lines; at finalize time the bound fields are snapshotted into the immutable sys_<X>InvoiceLine ledger. The per-line bindings align with the line fields the shopping-cart pricing settings produce (quantity, unitPrice, lineTotal, discountAmount, vatRate, vatAmount, finalTotal), so a cart's tax breakdown flows into the invoice losslessly. Only quantity/unitPrice/description are commonly needed — the tax-breakdown bindings are for lines that already carry computed VAT.

| `unitPriceProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Property of the line item object that stores the unit price. | `descriptionProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Property of the line item object that stores the human-readable line description shown on the invoice. |
| `lineTotalProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property holding the NET line total AFTER the discount and before VAT - the same field the shopping cart writes as lineTotal in both of its VAT modes. When unbound, derived at snapshot time: quantity × unitPrice − discountAmount for a net-priced line, and (quantity × unitPrice − discountAmount) / (1 + vatRate/100) for a line with pricesIncludeVat. A bound value that disagrees with that derivation is refused at invoice creation. |
| `discountAmountProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property holding the per-line discount amount. |
| `discountReasonProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: string property holding the per-line discount reason. Snapshotted onto the invoice line and emitted as cbc:AllowanceChargeReason inside a Turkish UBL discount allowance. Whitespace is trimmed and the text is XML-escaped; null or empty text emits no reason element. |
| `vatRateProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property holding the per-line VAT rate. Bind it when lines already carry computed tax (e.g. from shopping-cart pricing) so the invoice keeps the exact breakdown. |
| `vatExemptionCodeProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property of the line item object holding the line's GIB KDV exemption reason CODE - product data the merchant knows, e.g. 335 for printed books and periodicals (KDV 13/n), 301 for goods export, 351 for a 0% line that is NOT exempt. Snapshotted onto the invoice line (sys_<X>InvoiceLine.vatExemptionReasonCode) and threaded into the Turkish fiscal document, where it is the cbc:TaxExemptionReasonCode of that line's zero-VAT 0015 bucket; 0% lines are grouped per (rate, code), so two codes give two document TaxSubtotals. Read only for a 0% line: an unset or empty value falls back to the invoice-wide / fiscal provider entry vatExemptionReasonCode, then to 350; a code on a line whose VAT rate is not 0 is refused when the document is prepared (typed 400). The emitted codes decide the InvoiceTypeCode: any 2xx/3xx exemption code makes the document ISTISNA (taxed lines such as shipping at 20% stay on it), only 351 keeps SATIS; 7xx/8xx codes (IHRACKAYITLI / OZELMATRAH documents) are refused (typed 422). |
| `vatExemptionReasonProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property of the line item object holding the exemption reason TEXT that pairs vatExemptionCodeProperty. Unset or empty: the platform writes the OFFICIAL GIB text of the line's code (UBL-TR Kod Listeleri, e.g. 335 -> 'KDV 13/n Basılı Kitap ve Süreli Yayınların Teslimleri'), so bind it only for wording the list does not carry or for a code GIB added later. Meaningless without vatExemptionCodeProperty (WARNING). |
| `vatAmountProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property holding the per-line VAT amount. |
| `finalTotalProperty` | [`PropRefer`](./PropRefer.md) | no |  |  | names a [DataProperty](./DataProperty.md) from `lineItemObject` | Optional: property holding the final per-line total (after discount, including VAT). When unbound, derived at snapshot time: lineTotal + vatAmount for a net-priced line; for a line with pricesIncludeVat it IS the gross (quantity × unitPrice − discountAmount), the one field that carries the gross in that mode. |
| `pricesIncludeVat` | `Boolean` | no | `false` |  |  | Whether the bound unit prices (and discounts) are VAT-INCLUSIVE, the convention of a Turkish B2C catalogue and of a cart with pricingSettings.catalogPricesIncludeVat. Default false: prices are NET and VAT is added on top, so a 120 TRY price at 20% is invoiced as 120 + 24 = 144. When true, each line is priced GROSS-FIRST with the cart's rounding-exact extraction: gross = quantity × unitPrice − discountAmount, net lineTotal = gross / (1 + vatRate/100), vatAmount = gross − net (so net + VAT equals the gross exactly), finalTotal = gross; 120 at 20% is net 100 + VAT 20 = 120. lineTotal keeps ONE meaning in both modes, the net after discount (what the cart itself writes as lineTotal when it prices VAT-inclusive); in inclusive mode the gross is finalTotal. A bound lineTotal / vatAmount / finalTotal is validated against that extraction. Requires vatRateProperty: without a per-line rate there is no VAT to extract. |

## Constraints

Property rules:

- `hasLineItemRelation` must be present. (`REQUIRED_FIELD_MISSING`)
- `lineItemObject` must be a well-formed [`LocalDataObjectName`](./LocalDataObjectName.md) (a data object of the same service). (`INVALID_LOCAL_DATA_OBJECT_NAME_FORMAT`)
- `invoiceForeignKey`, `lineItemLocalKey`, `quantityProperty`, `unitPriceProperty`, `descriptionProperty`, `lineTotalProperty`, `discountAmountProperty`, `discountReasonProperty`, `vatRateProperty`, `vatExemptionCodeProperty`, `vatExemptionReasonProperty`, `vatAmountProperty`, `finalTotalProperty` must be a well-formed [`PropRefer`](./PropRefer.md) (a property of a data object). (`INVALID_PROP_REFER_FORMAT`)
