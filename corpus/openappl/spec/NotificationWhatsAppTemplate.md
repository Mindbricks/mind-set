# NotificationWhatsAppTemplate

**Level:** `subsection` · **Family:** [EventNotification](../ontology/families.md#eventnotification) (domain `NotificationService`)

**Ontology:** [NotificationWhatsAppTemplate in Part 1](../ontology/NotificationWhatsAppTemplate.md)

An approved WhatsApp template for a jobType='whatsapp' EventNotification: the Meta template name or the Twilio Content SID, its language, and the parameter scripts. Business-initiated WhatsApp messages must be template messages: free-form text is delivered only inside the 24-hour customer-service window. `components` and `contentVariables` are MScripts evaluated ONCE per event, against the same receiver as eventDataSettings.includeData (`this.payload` the event record, `this.dataSource` the DataView document when dataViewName is set, `this.old`, `this.actor`, `this.metadata` - the finished notification metadata, includeData entries included - and the bare root `data` = `this.dataSource ?? this.payload`). A script that throws, or that returns a value of the wrong shape, fails the delivery visibly (failed NotificationDeliveryLog + NotificationLog rows naming the slot); nothing is sent as free-form text in its place. Only the slot the provider reads is used: Meta reads name / language / components, Twilio reads name / contentVariables. LANGUAGE NOTE: implemented by the nodejs and dotnet notification listeners and providers; the other language targets still send free-form text.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `name` | `String` | yes |  |  |  | The template to send. For a Meta WhatsApp Cloud API provider (provider='whatsapp') this is the APPROVED template name as registered in WhatsApp Manager: lower-case letters, digits and underscores only (`^[a-z0-9_]+$`, e.g. `order_shipped`). For a Twilio provider (provider='twilio') it is the Content SID of the approved content template: `HX` followed by 32 lower-case hex digits (`^HX[0-9a-f]{32}$`). Case-sensitive and never rewritten (it is NOT a codeName). The format is checked at design time against the event's resolved provider (WHATSAPP_TEMPLATE_NAME_INVALID, ERROR). |
| `language` | `String` | no |  |  |  | The Meta template language code, exactly as the template is approved: `en`, `en_US`, `tr`, `pt_BR`. Optional. When empty it defaults to the language of the variant the recipient selected (with `-` turned into `_`), and to `en` for a recipient served by the template's own block with no variant. Twilio ignores it: a Content SID already names one language. |
| `components` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | Meta only. An MScript returning the template's `components` array, e.g. `[{ type: 'body', parameters: [{ type: 'text', text: this.payload.orderNumber }] }]`. The positional shorthand is accepted too: an array of plain values (`[this.payload.customerName, this.payload.orderNumber]`) is sent as the BODY text parameters {{1}}, {{2}}, ... in order. Leave empty for a template without parameters. Evaluated once per event (see NotificationWhatsAppTemplate for the scope). |
| `contentVariables` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | Twilio only. An MScript returning the Content API variables object, e.g. `{ '1': this.payload.customerName, '2': this.payload.orderNumber }`; an array is numbered from 1. Sent as `contentVariables: JSON.stringify(value)`. Twilio fills a missing variable from the content template's SAMPLE value, so declare every variable the template uses. Evaluated once per event (see NotificationWhatsAppTemplate for the scope). |
| `category` | `WhatsAppTemplateCategory` | no | `null` | `utility`, `marketing`, `authentication` |  | The Meta template category the template is submitted under: `utility` (a transactional update the recipient expects, e.g. an order confirmation), `marketing` (promotions, offers, re-engagement) or `authentication` (one-time passwords). Meta may re-categorise a template on review. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. Set it together with `body` (WHATSAPP_TEMPLATE_DOC_INCOMPLETE warns when one is set without the other). |
| `body` | `Text` | no |  |  |  | The Meta-approved BODY text of the template, with positional variables `{{1}}`, `{{2}}`, ... numbered from 1 without gaps, e.g. `Your order {{1}} has shipped; it arrives on {{2}}.` The positional `components` shorthand fills them in order. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. Validation (warnings): the placeholders must be numbered 1..N without gaps (WHATSAPP_TEMPLATE_PLACEHOLDERS_GAP), `samples` must carry one value per placeholder (WHATSAPP_TEMPLATE_SAMPLES_MISMATCH), and a positional-shorthand `components` array must carry N values (WHATSAPP_TEMPLATE_PARAMETER_COUNT_MISMATCH). |
| `header` | `String` | no |  |  |  | Optional TEXT header of the template, exactly as approved. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. |
| `footer` | `String` | no |  |  |  | Optional footer text of the template, exactly as approved. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. |
| `buttons` | [`WhatsAppTemplateButton`](./WhatsAppTemplateButton.md)[] | no |  |  |  | Optional buttons of the template, in the approved order: quick replies, a URL or a phone number. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. |
| `samples` | `String`[] | no |  |  |  | One sample value per body placeholder, in `{{1}}`, `{{2}}`, ... order (Meta requires a sample for every variable when the template is submitted), e.g. `["B261009-3LHPJQ", "530,00 TL"]`. Not a credential: printed verbatim in the DevOps guide. DOCUMENTATION ONLY: this field documents the template for its submission to Meta and is printed in the project's DevOps guide; it is NOT sent at runtime, because Meta renders the approved text itself. |

## Constraints

Property rules:

- `name` must be present. (`REQUIRED_FIELD_MISSING`)
- `category` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
