# ServiceOptions

**Level:** `section` · **Family:** [ServiceSettings](../ontology/families.md#servicesettings) (domain `Service`)

**Ontology:** [ServiceOptions in Part 1](../ontology/ServiceOptions.md)

Defines a configuration class for the basic options of the service for authentication, http and data model

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `serviceAllowsUserToLogin` | `Boolean` | no | `false` |  |  | Keep this false unless you know what you are doing. If true, the service provides login endpoints for users, allowing it to act as an authentication provider. This option is used if you want to make your own auth/user service instead of the default one created with authentication module configuration. |
| `httpPort` | `Integer` | no | `3000` |  |  | The port number that the service will use to listen for HTTP traffic. Recommended to use ports in the 3000-3099 range for consistency across microservices. The LOCAL dev env does not read this as a position: it derives a stable per-service port from the service name (the same name always gets the same port, and adding, removing or reordering services does not renumber the others), unless an explicit httpPort other than the 3000 default is authored, which is honoured there too. A literal 3000 is treated as unauthored. |
| `routerSuffix` | `String` | no |  |  |  | Retained deployment-path setting. Node.js currently does not consume it to rewrite service URLs before Express routing. Leading-prefix versus trailing-suffix matching, segment boundaries, non-match behavior, query preservation and auth/service precedence require a ruling. Leave null. |
| `dataModelName` | `String` | no | `"main"` |  |  | Retained data-model name/label. Node.js currently emits one data model per service; this field does not select a different model, connection or database schema. main/default are the documented aliases, while existing blueprints may carry other labels. Multiple-model selection and treatment of legacy labels require a ruling. |
| `dbType` | `DbTypes` | no | `"postgresql"` | `postgresql`, `mongodb` |  | Specifies the type of database engine used for storing the service's data. It must be one of the values in the DbTypes enum: postgresql (fully supported) or mongodb (beta). `mysql` was REMOVED from the vocabulary on 2026-08-01 — it was implemented only by the PHP / Laravel target, whose service codegen lane was retired on 2026-07-31. A service that still declares it is refused at design time (RETIRED_DB_TYPE) rather than silently downgraded to another engine. The engine also fixes the form of the framework's system-asset ids (root tenant, super admin, admin group and its member) at codegen: the canonical UUIDs on postgresql, their 24-hex ObjectId form on mongodb. The service's seeds write that form for the row ids AND for every reference to them, and the generated comparisons (session config, root tenant checks, the PBAC tenant clause, the tenant-move guard) compare that form; nothing decides it at runtime. |
| `postgresMajorVersion` | `Integer` | no |  |  |  | Optional declared PostgreSQL server major version. Required and at least 15 when a CompositeIndex opts into nullsNotDistinct. It describes the deployment target; it does not upgrade a server. MongoDB does not use this field. |
| `useSoftDelete` | `Boolean` | no | `true` |  |  | Indicates whether records are soft-deleted (i.e., marked inactive using an 'isActive' flag) instead of being physically removed from the database. This setting applies globally unless overridden at the data object level. |
| `wrapMScriptExecution` | `Boolean` | no | `true` |  |  | Default true retains framework runMScript runtime error tracing in generated Node.js MScript expressions. Explicit false bypasses supported direct two-argument calls whose binding resolves to the framework runtime import or require; user-defined, shadowed or unproven bindings remain intact. For bypassed calls, callback and metadata expressions retain call-order evaluation, callback lexical or bound this, return values and original throws/rejections; framework diagnostic classification is omitted. Omitted or true leaves source output unchanged. Use false only after thorough testing. |
| `blockedM2MClients` | `String`[] | no |  |  | format [codeName](./value-formats.md#codename) | An array of service names that are blocked from accessing this service using machine-to-machine tokens. Services listed here cannot call this service's APIs with machine tokens. However, blocked services can still access public APIs (loginRequired: false) and can trigger event-based functions on behalf of users when using user tokens. This provides fine-grained control over inter-service communication while maintaining flexibility for public endpoints and user-initiated actions. This is the DENY list of the M2M caller gate; it is a SECOND-LEVEL guard that only narrows callers whose M2M token ALREADY verified against the issuing service's JWKS — it is never authentication. When both lists are configured, this one WINS: a caller named here is refused even if `allowedM2MClients` also names it. Names are matched case-folded (they are `codeName` values). Renamed from `machineToMachineBlockList` on 2026-08-01 for symmetry with `allowedM2MClients`; the old spelling is refused at design time. |
| `allowedM2MClients` | `String`[] | no |  |  | format [codeName](./value-formats.md#codename) | An array of service names that are allowed to access this service using machine-to-machine tokens. When non-empty, ONLY services listed here may call this service's APIs with an M2M token; every other caller is refused with 403 `M2M_CLIENT_NOT_ALLOWED`. When empty, every caller presenting a valid M2M token is allowed (subject to `blockedM2MClients`). This is the ALLOW list of the M2M caller gate; it is a SECOND-LEVEL guard that only narrows callers whose M2M token ALREADY verified against the issuing service's JWKS — it is never authentication. `blockedM2MClients` wins when a name appears on both. Names are matched case-folded (they are `codeName` values). The gate applies to the M2M path only: a caller that is not on this list still reaches `loginRequired: false` APIs and still works through a user token. |
| `secureEvents` | `String`[] | no |  |  |  | Event ALIASES (NOT raw topic strings) on which the project's Ed25519 signature is required. Use the short alias form designers already write everywhere else — e.g. `userCreated`, `paymentSucceeded`, `order-cancelled`. The runtime maps each alias to its full Kafka topic name (typically `<projectCodename>-<serviceName>-<objectName>-<action>`) via the registered topicAliasResolver (see _common/<lang>/.../topic-alias). On the **publish** side: when this service emits an event whose alias is listed here, the publisher wraps the payload as `{ payload, sig, kid, jwks_url }` before placing on the resolved topic. On the **subscribe** side: when this service consumes an event whose alias is listed here, the subscriber verifies the signature and drops the message on failure. Use across trust boundaries — payment confirmations, audit-trail writes, cross-tenant fan-outs. |
| `publishes` | `String`[] | no |  |  |  | Kafka topics this service publishes from designer code that is NOT a library module, declared so the project's producer census counts them as produced. Prefer declaring on the library function that publishes (`library.functions[].publishes` / `library.edgeFunctions[].publishes`); use this service-level list for a publish the census cannot attribute to a module, e.g. an inline lifecycle-hook script. Same contract as `LibModule.publishes`: the wire name of each topic, codename-prefixed when it sits in a service's framework namespace (`<projectCodename>-<serviceName>-service-<event>`), as authored otherwise; an unprefixed framework-namespace name or a malformed topic is a design-time error. Without a declaration a subscription to such a topic is reported as producerless (`KafkaSubscriptionsWithoutProducer` at boot, `KAFKA_TOPIC_NO_PRODUCER` at design time). |

## Constraints

Property rules:

- `dbType` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `blockedM2MClients`, `allowedM2MClients` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `INVALID_HTTP_PORT` | error | httpPort … is out of range. |
| `RETIRED_DB_TYPE` | error |  |
