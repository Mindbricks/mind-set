# MailAccount

**Level:** `subsection` · **Family:** [ProjectSettings](../ontology/families.md#projectsettings) (domain `Project`)

**Ontology:** [MailAccount in Part 1](../ontology/MailAccount.md)

**Name:** an instance is named by `name`.

**Provider catalog:** the configuration keys of each brand are in [mailAccount](./providers/mailAccount.md).

A named mail account — a real mailbox the project can listen to, check, read, and send from (docs/ADR-mail-account-family.md). The `name` is the lookup key used by mail actions (check / read / send-on-behalf reference an account by name) and the env-var prefix (e.g. `support` → `MAIL_ACCOUNT_SUPPORT_*`). The `platform` enum selects the connector: `imapSmtp` speaks RFC-standard IMAP (listen/read) + SMTP (send) and works against any standards-compliant host — including Gmail and Microsoft 365 when paired with authKind=xoauth2; `gmail` selects the native Gmail API connector (users.messages/history, users.watch push); `microsoftGraph` selects the native Microsoft Graph connector (/me or /users/{address} messages, change-notification subscriptions with delta-query polling fallback). The `authKind` selects the credential model: `password` is basic auth and is valid ONLY for imapSmtp (Google and Microsoft retired basic auth on their mailboxes); `xoauth2` is the OAuth2 bearer model (SASL XOAUTH2 on IMAP/SMTP, native OAuth on the API connectors). The `configuration` is a free-form key/value list whose required keys depend on the (platform, authKind) pair; blueprint validation rejects incomplete combos.

Expected configuration keys per (platform, authKind):
- imapSmtp + password: imapHost, smtpHost, username, password (secret). Optional: imapPort (default 993), smtpPort (default 587), imapSecure (default true), smtpSecure (default false = STARTTLS on 587).
- imapSmtp + xoauth2: imapHost, smtpHost, username, clientId, clientSecret (secret), refreshToken (secret), tokenUrl (the OAuth2 token endpoint, e.g. https://login.microsoftonline.com/<tenant>/oauth2/v2.0/token). Optional: imapPort, smtpPort, imapSecure, smtpSecure, scope.
- gmail + xoauth2: clientId, clientSecret (secret), refreshToken (secret). The account `address` doubles as the API principal. Optional: tokenUrl (default https://oauth2.googleapis.com/token), scope, pubsubTopic (full Pub/Sub topic name for users.watch push wake-ups — operator setup in the ADR).
- microsoftGraph + xoauth2: tenantId, clientId, clientSecret (secret) — app-only client-credentials against Microsoft Graph (the dynamics365 enterprise-integration precedent). Optional: tokenUrl (default the tenant-scoped Azure AD v2.0 endpoint https://login.microsoftonline.com/<tenantId>/oauth2/v2.0/token), scope (default https://graph.microsoft.com/.default), refreshToken (secret — opt into the delegated flow, addressing /me instead of /users/<address>), notificationUrl (a public HTTPS callback for a Graph change-notification subscription — operator setup in the ADR).
- gmail + password / microsoftGraph + password: INVALID — both platforms retired basic auth; validation rejects the combo (MAIL_ACCOUNT_INVALID_AUTH_KIND).

Secret keys (password, clientSecret, refreshToken) are masked in API responses and emitted to MAIL_ACCOUNT_<NAME>_<KEY> env vars at codegen time.

Owner scope: `ownerScope` absent or `project` is everything above. `tenant` / `user` make the entry a MAILBOX TEMPLATE (see the ownerScope field): no `address`, no username / refreshToken / password in `configuration` (the owner's connection supplies the IMAP login and the credential), and `maxMailboxesPerOwner` (unset = 5, bounds 1 to 20) and `inlineBody` (unset = false, metadata-only events) apply. Required template keys per (platform, authKind): imapSmtp + password: none (imapHost / smtpHost optional: set, they fix the server; unset, the owner names a server at connect time, validated to public DNS on fixed ports); imapSmtp + xoauth2: imapHost, smtpHost, clientId, clientSecret (secret), tokenUrl; gmail + xoauth2: clientId, clientSecret (secret); microsoftGraph + xoauth2: tenantId, clientId, clientSecret (secret); the token endpoint is built from tenantId: a directory id admits that directory's mailboxes only, `organizations` (or `common`) admits any work or school directory of a multi-tenant app. The OAuth app keys stay project secrets on the MAIL_ACCOUNT_<NAME>_* env path.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `name` | `String` | yes |  |  | format [codeName](./value-formats.md#codename) | Unique account identifier within the project. Used as the lookup key from mail actions and as the env-var prefix (MAIL_ACCOUNT_<NAME>_*). Must be a valid codeName. |
| `ownerScope` | `MailAccountOwnerScope` | no | `"project"` | `project`, `tenant`, `user` |  | Who owns the mailbox behind this entry. `project` (the default; an absent ownerScope is project) is the single mailbox the project itself owns: its address and every credential are on this entry, secrets delivered as MAIL_ACCOUNT_<NAME>_* deploy env. `tenant` and `user` turn the entry into a MAILBOX TEMPLATE: it fixes the platform, the authKind, the OAuth app (clientId, clientSecret, tokenUrl, tenantId: project secrets on the same MAIL_ACCOUNT_<NAME>_* env path), the listen settings and the send / reply flags, and each owner connects their own mailboxes to it, at most `maxMailboxesPerOwner` each. With `tenant` the owner is a tenant and a tenant admin connects the mailbox (a shared info@ inbox); `tenant` needs a multi-tenant project (MAIL_ACCOUNT_TENANT_SCOPE_SINGLE_TENANT). With `user` every user connects their own company mailbox; `user` needs the auth service, i.e. a configured authentication module (MAIL_ACCOUNT_USER_SCOPE_NO_AUTH). The owner's credential (refreshToken for xoauth2, password for password auth), the IMAP login and the mailbox address come from the owner's connection, never from the blueprint: a template leaves `address` empty (MAIL_ACCOUNT_TEMPLATE_ADDRESS) and refuses username / refreshToken / password in `configuration` (MAIL_ACCOUNT_TEMPLATE_OWNER_CREDENTIAL). Template mailboxes are run by the mcpbff, the mail runtime: its manifest lists a template as a dynamic account with no env lookup for owner credentials. A mail action in a nodejs, rust, dotnet or java service names a template together with a runtime `mailbox` reference (the mailbox of the triggering event, or the session owner's own mailbox; the codename alone is MAIL_ACCOUNT_TEMPLATE_STATIC_REFERENCE); in a service whose language has no template support a template is refused (MAIL_ACCOUNT_TEMPLATE_LANGUAGE_UNSUPPORTED); project accounts work in every language as before. The mcpbff listens to every connected mailbox of a template with autoListen and publishes each message as an owner-stamped event (tenantId, ownerUserId or the owner tenant, the mailbox, the message id and its metadata) on the project-scoped wire name of the template's listenTopic, `<projectCodename>-<listenTopic>`, keyed by mailbox; a listening template may not share a listenTopic with a listening project account (MAIL_ACCOUNT_TEMPLATE_TOPIC_SHARED). |
| `address` | `String` | no |  |  |  | The mailbox email address this account represents (e.g. support@acme.com). Used as the From/Sender identity for on-behalf sends and as the API principal for the native connectors. Required on a project account; left empty on a template (ownerScope tenant or user), where every connected mailbox brings its own address (MAIL_ACCOUNT_TEMPLATE_ADDRESS). |
| `platform` | `MailAccountPlatform` | no | `"imapSmtp"` | `imapSmtp`, `gmail`, `microsoftGraph` |  | The mailbox platform connector. `imapSmtp` is the standards-based connector (any IMAP/SMTP host, including Gmail and Microsoft 365 via xoauth2); `gmail` selects the native Gmail API connector; `microsoftGraph` selects the native Microsoft Graph connector. Decides which keys are expected in `configuration`. |
| `authKind` | `MailAccountAuthKind` | no | `"password"` | `password`, `xoauth2` |  | The credential model. `password` = basic username/password auth, valid only for platform=imapSmtp (Google/Microsoft retired basic auth). `xoauth2` = OAuth2 bearer credentials (SASL XOAUTH2 for imapSmtp, native OAuth for gmail/microsoftGraph). |
| `autoListen` | `Boolean` | no | `false` |  |  | When true, the mcpbff bridge host watches this mailbox (IMAP IDLE / API subscription) and publishes every new message as a normalized envelope to the Kafka topic in `listenTopic`. When false, the mailbox is only reachable on demand through mail actions. |
| `listenTopic` | `String` | no | `"new-email-arrived"` |  |  | Kafka topic the listener publishes normalized inbound-mail envelopes to. Defaults to the project-wide `new-email-arrived`; override per account to route a mailbox to its own topic (e.g. a dedicated topic for invoices@). A project account publishes its bare envelope on exactly this name; a mailbox template (ownerScope tenant or user) publishes its owner-stamped events on the project-scoped wire name `<projectCodename>-<listenTopic>` (a Kafka controller naming the bare topic is scoped onto it), so a listening template and a listening project account may not share one listenTopic (MAIL_ACCOUNT_TEMPLATE_TOPIC_SHARED). |
| `markAsSeen` | `Boolean` | no | `true` |  |  | When true (default), the listener flags a message as seen on the mailbox only AFTER its envelope is successfully published to Kafka — an unseen message always means an undelivered envelope, and a crash between fetch and publish redelivers rather than drops. Set false to leave the mailbox untouched (e.g. when humans share the inbox). |
| `sendEnabled` | `Boolean` | no | `true` |  |  | When true, send actions may originate new mail on behalf of this account. Disable for listen-only mailboxes (e.g. an intake address that must never send). |
| `replyEnabled` | `Boolean` | no | `true` |  |  | When true, send actions may reply within an existing thread on behalf of this account (threading via inReplyTo/references headers). Disable to allow only fresh outbound mail — or combine with sendEnabled=false for a fully read-only account. |
| `maxMailboxesPerOwner` | `Integer` | no | `null` |  |  | Template only (ownerScope tenant or user): the most mailboxes ONE owner (one tenant, or one user) may connect to this template. Unset reads 5. Bounds: 1 to 20 inclusive (MAIL_ACCOUNT_MAX_MAILBOXES_OUT_OF_RANGE); the scoped-credential store that holds the connected mailboxes applies the same default and ceiling. Refused when set on a project account (MAIL_ACCOUNT_TEMPLATE_KEY_ON_PROJECT), which is exactly one mailbox; unset is accepted there. |
| `inlineBody` | `Boolean` | no | `null` |  |  | Template only (ownerScope tenant or user): when true, the inbound-mail event of a connected mailbox also carries the message body (text and html). Unset or false (the default) publishes metadata only: from, to, subject, date, attachment metadata, message id, tenantId, ownerUserId and mailbox; a consumer reads the body on demand through ReadMail. Refused when true on a project account (MAIL_ACCOUNT_TEMPLATE_KEY_ON_PROJECT), whose event shape is unchanged; unset or false is accepted there. The body on the bus is the one exception to metadata-only: set it only when every consumer of the template's topic may read the owners' mail. |
| `configuration` | [`DataMapSimpleItem`](./DataMapSimpleItem.md)[] | no |  |  |  | Free-form key/value list of connection settings and credentials. The required keys depend on the (platform, authKind) pair — see the MailAccount doc string for the per-combo key list. Sensitive keys (password, clientSecret, refreshToken) are masked in API responses and emitted to MAIL_ACCOUNT_<NAME>_* environment variables at codegen time. |

## Constraints

Property rules:

- `name` must be present. (`REQUIRED_FIELD_MISSING`)
- `ownerScope`, `platform`, `authKind` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `name` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)
- The items of `configuration` must have distinct names (`name`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `UNIQUE_MAIL_ACCOUNT_NAME` | error | Mail account name "…" is used by … entries in projectSettings.mailAccountsSettings.mailAccounts[]. |
