# AgentToolSettings

**Level:** `section` · **Family:** [AIAgent](../ontology/families.md#aiagent) (domain `Service`)

**Ontology:** [AgentToolSettings in Part 1](../ontology/AgentToolSettings.md)

Configures which tools the agent can invoke during its execution loop. Only applicable for text and vision modality agents. Tools follow the OpenAI/Anthropic function calling convention. The agent's tool-calling loop continues until the model stops requesting tools or the maxToolCalls guardrail is hit.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `enableCrudTools` | `Boolean` | no | `false` |  |  | When true, auto-generates tool definitions from the service's DataObjects, exposing create/read/update/delete/list operations. Uses the same schema generation as the MCP layer. |
| `crudScopes` | `String` | no |  |  |  | Comma-separated allow-list of DataObject names to expose as CRUD tools. Empty means NO CRUD tools are generated (explicit opt-in per object — the old expose-everything default was removed with the WS2 security floor). Each entry must name a DataObject of the host service (existence-checked at design time). Example: 'User,Order,Product'. A CRUD operation with a matching BusinessApi runs through that api with the CALLER's identity (roles, ownership and `permissionCheck` decided as over REST; a `permissionCheck` api refuses a run with no HTTP caller). |
| `apiTools` | `String` | no |  |  |  | Comma-separated list of BusinessApi names to expose as callable tools. Each API becomes a tool the agent can invoke. Example: 'sendNotification,calculatePrice'. A tool bound to a BusinessApi of the agent's own service runs that api's auth gates for the CALLER, exactly as the same caller's REST call: a `permissionCheck` api is decided by the caller's session manager, and is refused (403) on a run with no HTTP caller (Kafka- or cron-triggered, or resumed). Only a run started by the agent's own HTTP request carries the session manager, so the same refusal applies, even with a real user behind the run, to a Telegram or WhatsApp chat-surface message, the hub's eval suite and a programmatic executeAgent run (an in-process AgentCallAction, the video live pipeline); gate the apis such runs call with checkRoles, absoluteRoles or ownershipCheck. |
| `m2mTools` | `String` | no |  |  |  | Comma-separated SUBSET of apiTools that must execute over a MACHINE (M2M) identity instead of the caller's own. This is the per-tool AUTH ARM declaration and it is the DESIGNER'S security decision — the agent never chooses, is never offered a credential, and cannot widen its own authority by reasoning about it; the arm is resolved from this list before the model is shown the tool. DEFAULT (a name absent here) is the USER arm: the tool call runs under the identity the agent itself is running as — the `actor` carried on the triggering event, or the session of the HTTP caller — so the target BusinessApi's own checkRoles/ownership gates keep deciding exactly as they would for that user calling directly. Name a tool here ONLY when the operation is a background or elevated one the acting user is not entitled to perform (an approval, a moderation verdict, a system reconciliation): the M2M arm carries roleId 'system' and therefore passes NO role gate, so the target api must be reachable over M2M — an entry whose api is not M2M-allowed is a design-time error, and the target service's serviceSettings.serviceOptions.allowedM2MClients still decides whether this project's agent host is an admitted caller. Every entry must also appear in apiTools. Example: apiTools 'getOrder,approveRefund' with m2mTools 'approveRefund'. |
| `agentTools` | `String` | no |  |  |  | Comma-separated list of other AI agent names to expose as tools. Enables cross-agent delegation — a text agent can invoke an image agent to generate visuals. Example: 'imageGenerator,translator'. |
| `libraryTools` | `String` | no |  |  |  | Comma-separated list of service library function names to expose as tools. Each function becomes a callable tool with auto-generated parameter schemas. Example: 'formatCurrency,geocodeAddress'. |
| `customTools` | [`AgentCustomTool`](./AgentCustomTool.md)[] | no |  |  |  | Custom tool definitions with explicit name, description, JSON Schema parameters, and a handler function reference. Use when you need tools that don't map to existing CRUD, API, or library functions. |
| `integrationTools` | [`AgentIntegrationToolConfig`](./AgentIntegrationToolConfig.md)[] | no |  |  |  | Integration providers to expose as agent tools. Each entry maps a project integration to tool definitions. Explicit method names create individual tools with full JSON Schema parameters. Wildcard '*' creates a single dispatcher tool with a getIntegrationMethodDoc helper for looking up exact signatures on demand. |
| `approvalRequiredTools` | `String` | no |  |  |  | Comma-separated list of TOOL names (as registered on the agent's tool registry) that require HUMAN APPROVAL before they execute. When the model calls one of these tools the run PAUSES in the 'paused_approval' state — persisted ending at the assistant tool-call turn, the tool has NOT fired — and surfaces on the approval API of the service that ran it (GET /agent-runs/pending): the hub's for a run started on the hub, and on nodejs the serving business service's own for a run started on that service's agent route. An approver (hubSettings.hubBasics.approvalRoles) then approves (the tool executes and the run resumes through its tool journal — already-completed tools are never re-executed) or rejects (the model receives a clean rejection tool_result and the run continues without the tool's effect). Use the REGISTERED tool names: CRUD tools are '<op>_<objectName>' (e.g. 'delete_order'), api tools use the BusinessApi name, agent tools are 'invoke_agent_<agentName>', integration tools 'integration_<provider>_<method>' (or 'integration_<provider>' for a wildcard dispatcher), custom and library tools their declared names. The common top-level agent.approvalExpiryDays controls this pause duration, shared with outputSettings.requiresApproval; null/unset disables expiry. Example: 'delete_order,refundPayment,integration_stripe_createRefund'. |
| `enableBatchApiCall` | `Boolean` | no | `false` |  |  | When true, the agent also gets the built-in `batch_api_call` tool: one tool call that runs up to guardrails.maxToolCalls (default 25, never more than 50) calls of this agent's own apiTools (in-process and cross-service; not CRUD, agent, library, custom or integration tools) in one step, `{ calls: [{ tool, args }], stopOnError? }`, at most 4 at a time. Each inner call runs exactly as a direct call would: under the caller's session, with the same guest, role and required-argument checks, the api's own gates and its `fields` projection, and gets its own `{ index, tool, ok, result \| error }` entry. A tool listed in approvalRequiredTools, or one the guardrails.decisionGate covers, cannot run inside a batch (that item is refused, the call is not made); put `batch_api_call` itself in approvalRequiredTools to approve a whole call list at once. Use it for bulk work the user has already confirmed. Node.js only for now. Default: false. |

## Constraints

Property rules:

- The items of `customTools` must have distinct names (`name`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
- The items of `integrationTools` must have distinct names (`integrationName`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `AGENT_M2M_TOOL_API_NOT_M2M_ALLOWED` | error | m2mTools entry "…" runs this tool over the machine (M2M) identity, but the BusinessApi "…" on service … is not M2M-reachable — …. |
| `AGENT_M2M_TOOL_NOT_IN_API_TOOLS` | error | m2mTools entry "…" is not one of this agent's apiTools (…). |
| `AGENT_TOOL_AMBIGUOUS` | warning | Tool name "…" is registered by more than one source (…) in this toolSettings section — only one implementation ends up in the agent's tool registry, chosen by registration order. |
| `UNKNOWN_AGENT_TOOL` | warning | agentTools entry "…" does not match any declared agent (service or hub). |
| `UNKNOWN_APPROVAL_TOOL` | warning | approvalRequiredTools entry "…" does not match any tool registered by this toolSettings section — the approval gate cannot attach. |
