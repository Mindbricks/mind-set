# ProjectSettings

**Level:** `chapter` · **Family:** [ProjectSettings](../ontology/families.md#projectsettings) (domain `Project`)

**Ontology:** [ProjectSettings in Part 1](../ontology/ProjectSettings.md)

Defines the core configuration of your OpenAPPL project, including metadata, environment preferences, and infrastructure settings. Use this section to set up the project name, description, Stripe payment settings, AI provider settings, CORS configuration, and custom CI/CD pipeline templates.

| `notificationProvidersSettings` | [`NotificationProvidersSettings`](./NotificationProvidersSettings.md) | no |  |  |  | Settings for notification providers (email, SMS, push, Telegram, WhatsApp). The generator emits NOTIFICATION_PROVIDER_<NAME>_* environment variables per provider so service code can construct an SDK client at runtime without revisiting the project config. Mail has a BUILT-IN fallback: if a selected email provider's credentials are incomplete at runtime, the framework sinks the message into a mock SMTP endpoint rather than failing, so mail flows are exercisable in preview without a real mailbox. The sink is framework-owned — it is never declared in this list — so declare your real provider (or none) and add no placeholder entry. A message to a RESERVED non-deliverable recipient (an email domain under .invalid, .test, .example or .localhost, example.com / example.net / example.org, or a phone number in the fiction ranges +1 NXX 555-0100..0199 and +44 7700 900000..900999) is always stored in the channel's built-in sink and never handed to a real provider, on every deployment including production, so demo data cannot get a provider account flagged for bounces. |

Each entry is a named provider referenced by DataObject `invoicing` opt-ins. NATIVE brands (internal, stripe, logoIsbasi, mikro, parasut, custom) carry credentials in their configuration[] and the generator emits INVOICE_PROVIDER_<NAME>_* environment variables per entry; BRIDGE brands (sap, dynamics365, netsuite, logoTiger) instead name an enterpriseIntegrationsSettings entry via `integrationName` and reach the platform through the mcpbff bridge — they carry no credentials of their own. The `internal` brand needs no entry at all: a data object whose invoicing.configuration.providerName is null binds the framework-native invoicing implicitly. | `fiscalProvidersSettings` | [`FiscalProvidersSettings`](./FiscalProvidersSettings.md) | no |  |  |  | Settings for fiscal providers — the integrators that submit documents into a government's fiscal infrastructure (e-invoice, e-archive, real-time reporting) for fiscalization-enabled data objects. Fiscalization is a SEPARATE axis from both payment and invoicing: an InvoiceProvider is the commercial system of record, a FiscalProvider is the regulatory transport (InvoiceProvider: logoTiger + FiscalProvider: foriba is a supported combination, and so is fiscalization with no invoice provider at all in reporting-only regimes). Each entry is a named provider referenced by DataObject `fiscalization` opt-ins; `provider` selects the adapter (v1 Turkey-first: elogo, foriba, nilvera, izibiz and uyumsoft all ship adapters; plus mock and custom), `network` names the government infrastructure it serves (GIB, SDI, KSeF, ...). There is NO internal brand — fiscalization always goes through an integrator or the mock adapter. Mirrors the invoiceProvidersSettings shape — a named array; multiple entries can share the same provider type. |
| `decisionProvidersSettings` | [`DecisionProvidersSettings`](./DecisionProvidersSettings.md) | no |  |  |  | Settings for calibrated decision providers — System One models that answer TYPED questions about a piece of state with a calibrated probability instead of generating text (docs/ADR-decision-layer-system-one.md). A decision layer is a SEPARATE axis from AI: a decision provider has no prompt, its answers are typed (noul probability / choice / score), and its output tokens are free, so the aiProvider surfaces (AIPromptTemplate, responseFormat, two-sided token budgets, the model price table) would state false things about it — that family split is ADR Decision 1. Each entry is a named provider referenced by decision-consuming patterns (DecisionAction, FuzzyDomainFilter, DataProperty.decisionSource); service code resolves it by name at runtime through DECISION_PROVIDER_<NAME>_* environment variables. Brands: typesafe (Jev), custom (a TypeSafe-wire-compatible endpoint, or the same interface emulated over an OpenAI/Anthropic structured-output call), and mock — a REAL keyless transport answering all three question types deterministically, so a build never blocks on a missing credential and CI never reaches the network (the payment MOCK_TRANSPORT_BRANDS precedent). NO authorization decision may ever come from a decision provider — a noul standing in for permissionCheck/membershipCheck/absoluteRoles is validation ERROR DECISION_ON_AUTHZ_SURFACE. Mirrors the bucketProvidersSettings shape — a named array; multiple entries can share the same provider type. |
| `socialLoginProvidersSettings` | [`SocialLoginProvidersSettings`](./SocialLoginProvidersSettings.md) | no |  |  |  | Settings for social login providers: the OAuth client each brand (google, apple, facebook, microsoft, linkedin, github, gitlab) signs users in with, one entry per brand. An entry in the list is active; a brand with no entry has no social login. This is the canonical location of social login credentials. The older `authentication.socialLogins` block is still read: an enabled legacy brand counts as an entry named after the brand, a provider entry wins over a legacy entry of the same brand (validation WARNING SOCIAL_LOGIN_PROVIDER_SHADOWS_LEGACY), and the moveSocialLoginsToProviders tool moves the legacy entries here on request. The auth service reads each entry through fixed env variables (GOOGLE_CLIENT_ID / GOOGLE_CLIENT_SECRET, FACEBOOK_APP_ID / FACEBOOK_APP_SECRET, MICROSOFT_CLIENT_ID / MICROSOFT_CLIENT_SECRET / MICROSOFT_TENANT, LINKEDIN_*, GITHUB_*, GITLAB_*, APPLE_CLIENT_ID / APPLE_TEAM_ID / APPLE_KEY_ID / APPLE_PRIVATE_KEY); secrets are masked in API responses and delivered as CI/CD variables, never committed. Per-environment clients come from the environment values of the entry (family socialLogin), not from a second entry. Missing credentials never block a build or the boot: the login route of the brand answers a typed 503 errMsg_OAuthProviderNotConfigured_<brand> until they are set. |

The `provider` brand decides which AMQP protocol the mirror speaks: `rabbitmq` / `cloudamqp` = AMQP 0-9-1, `artemis` / `azureServiceBus` = AMQP 1.0. The deployed mcpbff gets AMQP_<NAME>_* environment variables per provider: HOST, PORT, VHOST and USE_TLS as committed env lines on every slot, USERNAME, PASSWORD and CONNECTION_STRING as CI/CD variables of the mcpbff repo; no business service carries any. | `servicePlan` | [`ServicePlanEntry`](./ServicePlanEntry.md)[] | no |  |  |  | The microservice-definition plan carried into the blueprint FOR REFERENCE: the services the project intends to create. Written at design time (the designer agent is the usual author, but a hand-authored blueprint may set it too); absent on imported projects and on most hand-authored projects, and an absent plan changes nothing. The plan is NOT binding and NOT an inventory: a planned service that never gets built is not a defect, a service that exists but is not in the plan is not a finding, and the plan may be deleted once the last planned service exists. It has exactly one effect — a design-time reference into a service that does not exist yet is reported as a WARNING when the plan names that service, and stays an ERROR when it does not, which is the first time a forward reference is distinguishable from a typo. It never exempts anything at build or codegen time. |

## Constraints

Property rules:

- `basicSettings` must be present. (`REQUIRED_FIELD_MISSING`)
- The items of `pipelineTemplates` must have distinct names (`filename`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
- The items of `servicePlan` must have distinct names (`serviceName`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
