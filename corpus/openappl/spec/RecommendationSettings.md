# RecommendationSettings

**Level:** `section` · **Family:** [ObjectSettings](../ontology/families.md#objectsettings) (domain `DataObject`)

**Ontology:** [RecommendationSettings in Part 1](../ontology/RecommendationSettings.md)

**Activation:** the pattern is switched on by `enabled`.

Recommendation lists of a data object as the ITEM being recommended (docs/ADR-recommendation-engine.md section 4). The pipeline per list: candidate generation from precomputed neighbor / popularity tables, deterministic filtering, scoring and ranking, list policy, serving with a `listRequestId`, impression logging. The lists live on the item's own service and inherit the item's read gate, tenant scope and visibility. No authorization or filtering decision may come from a recommendation score or a decision provider (ADR hard rule 1).

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `enabled` | `Boolean` | yes |  |  |  | Turns recommendations on for this object. False (the default) leaves the block inert: no neighbor or popularity table, no refresh cron, no serving api, and the object is generated exactly as without the block. The other fields are only checked while this is true. |
| `sources` | [`InteractionSource`](./InteractionSource.md)[] | no |  |  |  | Interaction sources DECLARED for this object's lists (`from: declared`), for a hand-modelled data model: the event object and a property path per role. Sources a pattern publishes (a catalog-bound shopping cart, visit tracking, ...) are discovered automatically and are never stored here, so they cannot go stale against the pattern. |
| `lists` | [`RecommendationList`](./RecommendationList.md)[] | no |  |  |  | The recommendation lists of this object. Each list is served under the object's own routes and carries the relation and the signal that produced each item, so the UI wording stays true. |

## Constraints

Property rules:

- `enabled` must be present. Enforced only while `enabled` is on. (`REQUIRED_FIELD_MISSING`)
- The items of `sources` must have distinct names (`name`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
- The items of `lists` must have distinct names (`name`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
