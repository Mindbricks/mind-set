# BusinessApiParameter

**Level:** `section` · **Family:** [BusinessApiParameters](../ontology/families.md#businessapiparameters) (domain `BusinessApi`)

**Ontology:** [BusinessApiParameter in Part 1](../ontology/BusinessApiParameter.md)

**Name:** an instance is named by `name`.

Defines a customizable input parameter for a Business API. Parameters are extracted from the incoming request, transformed and validated, and then written directly to the API context under `this.<name>`. These parameters may originate from any request part (e.g., body, query, session), and can be combined with Redis-based or auto-generated parameters.

| `name` | `String` | yes |  |  | format [codeName](./value-formats.md#codename) | The name of the parameter in the API context. The value will be available at `this.<name>` during Business API execution. This does not need to match the incoming request key. Because the value binds as `this.<name>` on the generated manager, the name must not collide with a member of the manager base class chain (e.g. `request`, `output`, `execute`, `checkRoles`) - such a parameter would overwrite the manager's own member and break the request pipeline, so validation refuses it (BUSINESS_API_PARAM_RESERVED_NAME). Exception: a parameter that writes a same-named data property of the api's object is allowed - that is the normal explicit-mode write path. That exception is not free: the emitted field still overwrites the base member at construction, so validation reports it as a warning (PARAM_SHADOWS_MANAGER_MEMBER) naming what the manager loses - rename the DATA PROPERTY to clear it. Only members the runtime captures privately are silent, and today those are `name` (the api name is read from a private slot, so a `name` parameter no longer disarms idempotent replay or the login gate exemptions), `controllerType` (the transport is read from a private slot, so a `controllerType` parameter cannot make a caller a trusted system job) and `auth` (the caller's session manager is read from a private slot, so an `auth` column is plain data and never stands in for the caller at any gate). The name `session` is refused outright, in every language (ERROR PARAM_NAMED_SESSION): designer MScript reads `this.session` as the caller's session, and a parameter of that name would bind the request's value there. That covers a parameter writing a `session` data property too - rename the data property (e.g. `sessionValue`) and the parameter with it. The ERROR blocks saving the slice and building; it is not in the non-bypassable security list, because the framework's own gates read the caller's session from a private slot. |

| `isArray` | `Boolean` | no | `false` |  |  | Set to `true` when the parameter accepts an array of values (e.g. `String[]`, `ID[]`, `Integer[]`). In nodejs, a present non-array value for a caller-authored array parameter is refused with HTTP 400 `INVALID_PARAMETER_TYPE`, naming the parameter, before vocabulary validation; this also applies on MongoDB and on Kafka, internal-call and streaming paths. Optional null or absent values and array values are unchanged. Query and header scalars retain their one-element-array read lift; session, header, cookie and request locations and geo or row-id parameters are excluded from this shape gate. This flag MUST match the `isArray` setting on the matching data property to avoid a codegen mismatch error. For auto-generated parameters bound to a data property, this is backfilled automatically when omitted. |

| `defaultValue` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | Optional fallback used when the request omits this parameter — an MScript expression evaluated at request time and spliced into the generated handler as a PRESENCE test on the read (`(<read>) !== undefined ? (<read>) : <default>`): the default applies only when the key is ABSENT, and a caller that sends an explicit `null` binds `null`. One transport exception: on the gRPC arm a singular parameter whose type maps to a proto3 message (Object / Json / GeoPoint as `google.protobuf.Struct`, Date / DateTime / Time as `google.protobuf.Timestamp`) decodes as `null` when omitted and cannot carry an explicit null at all, so there a `null` read takes the default. Because it is an expression (not a raw literal), it can be a plain literal (`{ "js": "1" }`, `{ "js": "'USD'" }`) OR computed/context code (`{ "js": "this.session.userId" }`, `{ "js": "new Date()" }`, `{ "js": "LIB.common.uuid()" }`). Author literals with the value's own syntax (strings quoted); supply per-language sources when a native form is needed. Leave null for no default.  ENUM MEMBER SHORTHAND. When `type` is `Enum`, a defaultValue whose JS source is a SINGLE BARE IDENTIFIER textually equal to one of the `enumOptions` — `{ "js": "participant_cancel" }`, or the legacy plain-string form `"participant_cancel"` — is accepted as authoring shorthand: the shared pattern parse normalizes it to the quoted string literal (`{ "js": "'participant_cancel'" }`) and validation reports the rewrite through the autoFixes tier, never silently. Precedence when names collide: for an Enum-typed parameter the ENUM-MEMBER reading WINS over a slot binding or JS global of the same name — a bare `LIB` on a parameter whose enumOptions include `"LIB"` normalizes to `"'LIB'"`; anything more than a bare identifier (`LIB.today()`, `this.x ?? 'a'`) keeps its expression meaning and never normalizes. A bare identifier that is NOT an enum member does not normalize — in the `{ "js": … }` form it is a design-time ERROR (`MSCRIPT_UNKNOWN_ROOT_BINDING`: the splice scope is `this`, `LIB` and the JS/Node globals, so any other root identifier is a guaranteed TS2304 in the generated manager). |
| `httpLocation` | `RequestLocations` | yes |  | `bearer`, `cookie`, `header`, `query`, `body`, `urlpath`, `session`, `request` |  | The section of the HTTP request to extract the parameter from (e.g., `body`, `query`, `session`). Chosen from the `RequestLocations` enum. REQUIRED, and there is no schema default: an absent value is reported as REQUIRED_FIELD_MISSING, and a cased spelling (`Body`) is auto-corrected to the canonical enum member. Where a value nevertheless has to be resolved for a parameter that never passed validation (a legacy import, a partial subtree write), the fallback is METHOD-AWARE: an api whose effective HTTP method is GET or DELETE binds the parameter from the QUERY STRING, every other method from the BODY. Declaring `body` on a GET or DELETE is refused at design time (BODY_PARAM_ON_BODYLESS_METHOD) because no caller can send a body on those methods, so the parameter would read undefined on every call. One more override applies before any of this: when the parameter NAME matches a `:segment` of the api's effective route, the URL is the source of truth and the built api rebinds the location to `urlpath` (reported as an autoFix, REQUEST_PARAM_REBOUND_TO_URLPATH); give such a parameter no `dataPath`, or a `dataPath` equal to the segment name, or the generated reader looks up a key `req.params` does not carry. |
| `dataPath` | `String` | no |  |  |  | OPTIONAL - when omitted (or null) the parameter's own name is the path, which is what every read site already computes (`dataPath ?? name` in BusinessApiParameter); the field only needs authoring when the source key DIFFERS from the parameter name. It was formerly required, which made every flat parameter repeat its own name and made the framework's own injected builders (and the auth module) nonconforming. A dot-path expression to locate the parameter value in its specified source (e.g., `user.email`, `input.cart.total`). For flat parameters this is simply the parameter's own name (e.g. `phaseId` → dataPath `phaseId`). KAFKA-TRIGGERED APIs — read scope 'record': when the API is invoked through `controllers.kafkaSettings`, the source is the pseudo-request the generated Kafka controller builds as `body: _payload?.data ?? _payload`, i.e. the event record ALREADY UNWRAPPED out of the unified event envelope. Use the BARE key (`contentType`), NEVER a `data.` prefix: the envelope is stripped before `readKafkaParameters` runs, so `data.contentType` reads through a second, non-existent envelope and resolves to undefined at runtime. Note this is the opposite binding from an AIAgent `kafkaControllers[].dataMapping` that declares a mapping — that one is read scope 'envelope' (it is handed the raw wire message) and therefore does read `message.data.<key>`. The wire is enveloped for every topic without exception; what changes is whether your reader unwrapped it for you. ENVELOPE scope on kafka: a parameter whose `httpLocation` is `request` resolves against the RAW envelope instead of the record — the generated controller carries it on `_req.event` — so `old.archived` reads the pre-change row the framework publishes on every `.updated` db-change event, which is the only way to author an act-only-if-it-actually-changed consumer. Dotted paths are TRAVERSED on kafka and on the REST `request` location; every OTHER location on every other protocol brackets the whole string as a single key. Where a path is traversed, every hop is optional-chained, so a missing intermediate object binds undefined instead of throwing out of the parameter read. |
| `transform` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | An optional MScript expression to post-process the raw input before validation. This is useful for trimming, normalizing, or coercing types. THE VALUE IS `this.<parameterName>`, not `this`: the expression is spliced into a method of the generated api manager (`this.<name> = await Promise.resolve(<expr>)`), so `this` is the MANAGER. Write `this.title?.trim()`, never a bare `this` — a bare `this` does not throw, it writes the manager object into the column, and validate refuses it (`MSCRIPT_PARAMETER_BARE_THIS`). | `contractOnly` | `Boolean` | no | `false` |  |  | If `true`, the parameter is a CONTRACT-SURFACE declaration that the API intentionally does not consume: it is validated, typed and documented (REST doc, Swagger, MCP, test tooling) and the value is bound into the request context, but no whereClause, dataClause or action MScript is expected to read it and it is not expected to be stored. Typical uses: carrying a producer envelope key on an event-sourced API to document/enforce the producer's payload contract, reserving a field for a consumer that is wired later, or accepting a correlation token the framework handles elsewhere. Setting it suppresses the PARAM_UNUSED / PARAM_NOT_STORED / REQUIRED_PARAM_NOT_STORED advisories for this parameter and keeps it out of the UPDATE_WRITES_NOTHING dropped-parameter count. It is also THE sanctioned declaration for a parameter that carries the contract of a fully-parametric API whose work is done by an action: for example an M2M update that takes `orderId` / `lines` / `idempotencyKey`, has no dataClause (its columns may be `allowUpdate: false`) and hands the values to a LIB action that reads them as `this.<param>`. The wire contract and the `this.<param>` reads are unchanged; the parameter just stops implying a column write. Do NOT set it on a parameter that is supposed to be written to a column or to select the row: that would silence the exact finding that catches a silently dropped caller value. Defaults to `false`. |

## Allowed values

### DataTypes

`ID`, `String`, `Text`, `Integer`, `Boolean`, `Double`, `Decimal`, `Float`, `Short`, `Object`, `Date`, `Enum`, `GeoPoint`, `GeoRoute`, `GeoArea`, `Blob`

## Constraints

Property rules:

- `name`, `type`, `required`, `httpLocation` must be present. (`REQUIRED_FIELD_MISSING`)
- `type`, `httpLocation` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `name` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `API_HEADER_PARAMETER_RESERVED` | warning | Header parameter "…" reads the header "…", which is a reserved transport, auth or platform header. |
| `MCP_RESERVED_PARAMETER_NAME` | error | Parameter name "…" is reserved for the MCP auth envelope on a BusinessApi with apiOptions.mcpExposed === true. |
