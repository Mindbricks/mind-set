# DbBucketBasics

**Level:** `section` · **Family:** [DbBucket](../ontology/families.md#dbbucket) (domain `Service`)

**Ontology:** [DbBucketBasics in Part 1](../ontology/DbBucketBasics.md)

Core settings for the database bucket including its name, description, size limits, allowed file types, and antivirus scanning.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `name` | `String` | yes |  |  | format [codeName](./value-formats.md#codename) | Unique bucket identifier within the service. Used in route paths (/bucket/{name}/), table names ({name}File), and API names. Must be a valid codeName. |
| `description` | `Text` | yes |  |  |  | Human-readable description of what this bucket stores (e.g., 'User avatar images', 'Product photos', 'Signed contracts'). |
| `maxFileSizeMb` | `Integer` | no | `10` |  |  | Maximum allowed file size in megabytes. Files exceeding this limit are rejected at upload time. Default: 10 MB. |
| `allowedMimeTypes` | `String` | no |  |  |  | Comma-separated list of allowed MIME types (e.g., 'image/png,image/jpeg,application/pdf'). If null, all MIME types are accepted. Each entry is either an exact 'type/subtype', a family wildcard 'type/*' (so 'image/*' accepts image/png, image/jpeg and every other image subtype) or '*/*' (any type); matching is case-insensitive and ignores ';' parameters, and any other shape (no slash, '*/png', ...) fails generation naming the bucket and the entry. NOTE: the runtime additionally sniffs the file's magic bytes via the file-type package — a client-spoofed Content-Type header will be rejected when the sniffed type doesn't match. ACTIVE CONTENT (HTML, XHTML, SVG, every JavaScript type, XML and any +xml type) is kept as its type only when that exact type is listed here; a wildcard ('image/*', '*/*') or no list does not admit it. An upload whose bytes, declared type or file name say active content and that is not listed by its exact name is still accepted but stored as application/octet-stream, its original name kept and its active extension left out of the storage key. Every active object is served as a download, never rendered: DbBucket downloads always send X-Content-Type-Options: nosniff and Content-Disposition: attachment (plus Content-Security-Policy: default-src 'none'; sandbox for an active type), and a presigned download of an active object is signed with an attachment disposition and application/octet-stream. Generated by the nodejs, java, dotnet and python lanes. |
| `virusScan` | `Boolean` | no | `false` |  |  | When true, every uploaded file is scanned by ClamAV (configured under projectSettings.clamAvSettings, defaults to the platform ClamAV REST service at the default ClamAV host) before the file row is created. The scan is a property of the ROW, not of the upload route: EVERY path that creates a {name}File row runs it - the bucket's own upload route, a business api or designer action that writes the row itself (including a public loginRequired:false intake api, which cannot reach the upload route at all because DbBucketWriteLevel has no 'public' value), a bulk create, a seed and an in-process internal writer. An update that REPLACES the byte column is scanned too, so a clean insert followed by a payload update is not a way around it. Auto-promoted to true at generation time when bucketAuthorization.readAccess is 'public'. The outcome is recorded in the virusScanStatus column of the generated {name}File data object ('clean' \| 'infected' \| 'quarantined' \| 'error' \| 'skipped'), which the guard stamps on every scanned path - a caller cannot supply it. |
| `virusScanMode` | `BucketVirusScanMode` | no |  | `block`, `quarantine` |  | How a REJECTION is reported, and whether an infected file becomes a row at all. 'block' persists nothing: on the upload route the caller gets HTTP 422 VIRUS_DETECTED (or 503 VIRUS_SCAN_UNAVAILABLE when the scanner could not run) before any row exists, and at the row-creation seam the write is refused by a THROWN typed error carrying the same status and errorCode - a business api answers 422/503 with it, a designer action propagates it under its own error policy, and a seed or internal writer fails loudly. It is never reported in band as a success. 'quarantine' persists the row already carrying virusScanStatus='quarantined' and refuses downloads of it, which is useful when you want a forensic trail or to notify the user out-of-band. The scan is AWAITED before the write on every path, so a row never exists without a verdict and there is no 'pending' state. If null, falls back to projectSettings.clamAvSettings.configuration.defaultMode (default: 'block'). That resolution happens at DESIGN time and is baked into the generated service as a literal. A deployment can still override it at runtime by setting the CLAMAV_DEFAULT_MODE env var to 'block' or 'quarantine' (an operational escape hatch that works in both directions); leaving it unset, empty or unrecognised means no override and this per-bucket value wins. Whether a scan that could not RUN blocks is CLAMAV_ON_ERROR (runtime default reject): the generated dev, test (preview) and stage env files of a service with a virus-scanning bucket set it to skip, so an unreachable scanner records virusScanStatus='error' and lets the file through there, while prod keeps reject; a blueprint custom variable CLAMAV_ON_ERROR overrides it on every slot. Lane status: the row-level seam (scan before every row write, verdict stamped by the framework) is honoured in nodejs, dotnet and java, and emitted by the python and golang db layers too; the DbBucket upload-route scan is honoured in nodejs, dotnet and python (java has no DbBucket upload route yet), and golang bakes the per-bucket literal and lets CLAMAV_DEFAULT_MODE override it in both directions; rust honours it but cannot be overridden back down to 'block'. |

## Constraints

Property rules:

- `name`, `description` must be present. (`REQUIRED_FIELD_MISSING`)
- `virusScanMode` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `name` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)
