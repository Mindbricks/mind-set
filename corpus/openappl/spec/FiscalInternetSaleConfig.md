# FiscalInternetSaleConfig

**Level:** `subsection` · **Family:** [ObjectSettings](../ontology/families.md#objectsettings) (domain `DataObject`)

**Ontology:** [FiscalInternetSaleConfig in Part 1](../ontology/FiscalInternetSaleConfig.md)

Bindings sourcing the internet-sales content of a fiscal document from the owning DataObject. Some reporting regimes demand extra content for e-commerce sales (Turkey, VUK General Communique 509: an e-archive invoice for an internet sale must state the website, the payment method and date, the shipment date and a complete carrier party). Each slot binds a property of the owning object (PropRefer — per-row values) and, where the value is fixed per project, a static fallback; the website is static-only, since the sales channel does not vary per row. The carrier is declared by carrierMode: carrierCompany reads the carrier's legal title and VKN/TCKN from the designer's carrier data object (the carrier-company settings; OpenAPPL has no carrier system table) or from static values for a single-carrier shop, plus the tracking number; selfDelivery names the seller as the carrier; noShipment declares that nothing physical is shipped. An empty carrierMode reads as noShipment when no shipment slot (carrier source, legacy carrier name, shipment date, tracking number) is bound - a digital or service sale, with a WARNING - and as carrierCompany otherwise (maintainer ruling 2026-10-03). Never a name-only or empty carrier: a TR configuration without a carrier source is refused at design time and a carrier whose tax id does not resolve is refused before the integrator call. Slots left null are simply omitted from the document. The block is object-level (maintainer ruling 2026-10-03): once it binds anything, every row of the owning object is an internet sale - the phrase, the carrier per carrierMode, the ELEKTRONIK sending type - whatever that row's own slot values; an object that sells both in store and online is split into two objects or two fiscalization configurations. Kept deliberately lean per the FiscalPartyConfig doctrine — WHERE the values land on the document is the jurisdiction policy module's concern, not blueprint fields.

| `carrierMode` | `FiscalCarrierMode` | no | `null` | `carrierCompany`, `selfDelivery`, `noShipment` |  | How the goods of an internet sale reach the buyer, which decides the carrier party (cac:CarrierParty) the document names. carrierCompany: a shipping company carries the goods, and its legal title and VKN/TCKN come from the designer's carrier data object (carrierDataObject reached through carrierRefProperty) or, for a single-carrier shop, from carrierTitleStaticValue / carrierTaxIdStaticValue; the tracking number comes from trackingNumberProperty. selfDelivery: the seller delivers with its own vehicle or courier, so the carrier party is the seller's own title, VKN/TCKN and address - the same identity the document names as supplier (VUK 509). noShipment: nothing physical is shipped (a service, a subscription, a digital good), so the document carries no carrier party and no cac:Delivery; declare it only when that is true. OpenAPPL has no carrier system table: this binding IS the carrier settings, and the generated FiscalizationManager reads the referenced row when it builds the document. Read only when carrierMode is carrierCompany, or empty: a bound carrier data object is itself a shipment slot, so an empty carrierMode then reads as carrierCompany. ## Constraints

Property rules:

- `carrierMode` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `paymentMethodProperty`, `paymentDateProperty`, `shipmentCarrierProperty`, `shipmentDateProperty`, `carrierRefProperty`, `carrierTitleProperty`, `carrierTaxIdProperty`, `carrierAddressProperty`, `carrierDistrictProperty`, `carrierCityProperty`, `trackingNumberProperty` must be a well-formed [`PropRefer`](./PropRefer.md) (a property of a data object). (`INVALID_PROP_REFER_FORMAT`)
- `carrierDataObject` must be a well-formed [`LocalDataObjectName`](./LocalDataObjectName.md) (a data object of the same service). (`INVALID_LOCAL_DATA_OBJECT_NAME_FORMAT`)
