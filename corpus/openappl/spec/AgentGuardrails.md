# AgentGuardrails

**Level:** `section` · **Family:** [AIAgent](../ontology/families.md#aiagent) (domain `Service`)

**Ontology:** [AgentGuardrails in Part 1](../ontology/AgentGuardrails.md)

Safety limits and cost controls for the agent. Prevents runaway costs, excessive tool usage, and enforces input/output validation. These limits are enforced at runtime by the agent execution loop.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `maxToolCalls` | `Integer` | no | `25` |  | min 1 | Maximum number of tool invocations allowed per request. Prevents infinite tool-calling loops. Default: 25. |
| `maxTokenBudget` | `Integer` | no |  |  | min 1 | Maximum total tokens (input + output) allowed per request, cumulative across every provider call of the run (tool loop + structured-output repair loop). Enforced by the runtime from provider usage feedback (estimates where the provider reports none). The gate is PRE-CALL. On the FIRST call of a run (nothing produced yet) an over-budget estimate is refused before any spend with a typed 429 problem+json (errorCode AGENT_TOKEN_BUDGET_EXCEEDED) carrying the budget and the usage. Once the run has produced at least one model turn, reaching the budget FINISHES the run gracefully instead of aborting it: no further model turn is issued (tool calls the last model turn already requested still complete, so the conversation stays well-formed), and the run returns, on the same surfaces as a normal finish (the API response data, the SSE done event, the execution row output), a partial result { truncated: true, truncatedReason: 'tokenBudget', partial: <the last assistant text or null>, tokenBudget: { budget, used, estimated } } (plus validationErrors when the budget ran out before a structured-output or outputValidation repair turn; such a partial is never passed to outputValidation and never reported as a validation failure). The partial text is NOT schema-validated, responseProperty does not apply to it, and postProcess is skipped; the requiredToolCalls gate and the output approval hold still apply. An overshoot discovered only AFTER a provider call returned does not discard the finished answer: it is recorded and warned, and the run finishes before its next model turn. The daily per-user / per-tenant ceilings are separate guardrails and keep refusing with their own 429. Prevents excessive cost on a single request. |
| `maxToolResultChars` | `Integer` | no | `16000` |  | min 200 | Maximum size (in characters of the serialized result) a single tool result may occupy in the conversation. Larger results are truncated with an elision marker before being fed back to the model — a runaway list/query result cannot blow the context window. Default: 16000. |
| `elideToolResultsAfter` | `Integer` | no | `0` |  | min 0 | Tool-result elision, by count. When > 0, before EACH provider call of a run the runtime keeps the newest N tool results whole and replaces the content of every older one with a one-line stub (`[result of listOrders elided: 140 rows, 58213 chars; call the tool again if you need it]`). The tool_result itself stays in place (same tool-use id), so every tool call keeps its answer and no provider rejects the sequence; the results of the latest tool turn are never elided, and a stub is never re-elided. Use it on agents whose turns read large lists: each provider call re-sends every earlier result, so without elision the input of a long tool loop grows superlinearly. Combine with elideToolResultsOverChars to elide only the large ones. The elided conversation is also what the run checkpoints and a chat agent stores as history. The SSE client and the run event log still receive the full results. 0 (default) = off: the provider payload is unchanged. |
| `elideToolResultsOverChars` | `Integer` | no | `0` |  | min 0 | Tool-result elision, by size. When > 0, only an older tool result longer than this many characters is replaced with its one-line stub (see elideToolResultsAfter). With elideToolResultsAfter at 0, every result before the latest tool turn is a candidate; with both set, a result is elided when it is older than the newest N AND longer than this. 0 (default) = off. |
| `maxFileSizeMb` | `Integer` | no | `10` |  | min 1 | Maximum file size in MB for uploaded files. Enforced by the upload manager middleware. |
| `timeout` | `Integer` | no | `120000` |  | min 1 | Maximum execution time in milliseconds for a single agent request. Includes all tool calls and provider API calls. Default: 120000 (2 minutes). |
| `maxAgentDepth` | `Integer` | no | `3` |  | min 1 | Maximum agent-as-tool recursion depth. A direct caller (REST/SSE/kafka/internal) runs at depth 0; every sub-agent invocation (invoke_agent_* tools, orchestration steps) adds 1. Bounds cyclic/self-referential agent chains. Default: 3. |
| `inputValidation` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | MScript expression that validates the request input BEFORE any provider call. Return true to allow; false or a string error message to reject — a rejection is a clean 4xx-style error (statusCode 422), no tokens are spent and no run starts. Has access to 'this.request.body' / 'this.session', to 'this.source' and to 'this.onBehalfOf'. 'this.source' is the entry point the FRAMEWORK started the run from - 'rest' (the agent's REST route or the hub wildcard POST /agents/:agentName), 'sse' (a /stream route), 'kafka' (a kafkaControllers[] listener), 'eval' (the hub eval suite), 'internal' (programmatic executeAgent, e.g. an in-process AgentCallAction), 'telegram' / 'whatsapp' (chat surfaces), 'agent' / 'agent-tool' (an orchestration step or sub-agent tool). It is set from the route or listener that started the run and is never read from the request body or headers, so a body or header field named 'source' cannot set it: `this.source === 'kafka'` is a trustworthy gate for an event-only agent. 'this.onBehalfOf' is the identity a run acts for when it is NOT the run's session - on a Kafka run the event author ({ userId, roleId?, roles?, tenantId? } from the envelope actor; the run's session is the minted system session) - as data only, null on every other run. An expression that THROWS fails closed (the request is rejected with the evaluation error logged). |
| `outputValidation` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | MScript expression that validates the model's final output before returning/persisting. Return true to allow; false or a string to flag. Has access to 'result' (and 'this.request'). On failure: when modelSettings.strictOutput is true (default) the validation feedback is fed back to the model ONCE for repair, and a still-failing answer aborts the run with a clean error; when strictOutput is false the original output is returned with a logged annotation (AgentOutputValidationFailed). When guardrails.maxTokenBudget is reached before or inside that repair turn, the run finishes with the token-budget partial result (truncated: true, validationErrors) instead of a validation error. |
| `dailyTokenBudgetPerUser` | `Integer` | no |  |  | min 1 | Maximum total tokens (input + output) a single userId may consume per UTC day before this agent refuses to run for it. The tally is the service's: the in-process daily ledger is keyed by the userId and the UTC day only, so the provider usage of every agent of the same service process under that userId counts toward it. The userId is the run's SESSION identity: a Kafka-triggered run executes under the minted system session, so it is charged to that controller's system scope ('system:kafka:<agent>.<controller>', one shared daily bucket per controller), never to the event author's budget. Enforced BEFORE every provider call from the in-process daily ledger fed by real provider usage (the per-replica floor — cross-replica exactness is a deployment concern, like the run coordinator's session lock). Exceeding denies with a clean 429-style error before any further spend. Null = no per-user daily ceiling. |
| `dailyCostCeilingUsd` | `Double` | no |  |  | min 0 | Maximum estimated spend in USD per tenant per UTC day before this agent refuses to run (single-tenant projects, and tenant-less runs, use one global bucket). The tally is the service's: the in-process daily ledger is keyed by the tenant and the UTC day only, so by default the spend of every agent of the same service process in that tenant (or project) counts toward it; set costCeilingScope to 'agent' to compare it with this agent's own spend only. It is the guard that bounds a Kafka-triggered agent's daily spend, because its token budget is one shared bucket per controller. Cost is computed per provider call from the model price table — a versioned, dated built-in table (input, output, prompt-cache read and write prices per model, so cached prompt tokens are billed at their own rates), overridden by the blueprint's projectSettings.aiProvidersSettings.modelPrices entries and then by the AGENT_MODEL_PRICES env var (JSON map of model key → { inputPerMTok, outputPerMTok, cacheReadPerMTok, cacheWritePerMTok }), which merges last. The figure is an approximation from list prices. A model that matches no entry is priced by the '*' fallback (3/15 USD per 1M input/output tokens) and its cost is marked estimated: the runtime warns once per such model, the budget refusal names the model and the fallback, and validation warns (AGENT_COST_CEILING_UNPRICED_MODEL) when this ceiling is set on a model with no price entry. Enforced at the same deny-before-checkpoint seam as the token budgets; run records carry the accumulated tokenUsage.costUsd. Null = no cost ceiling. The hub eval runner (POST /agents/{name}/eval) runs an agent's evalSettings.evalCases only when this ceiling is declared (a value >= 0): eval cases are real runs charged to the calling approver's tenant, and this is their per-tenant bound. |
| `costCeilingScope` | `AgentCostCeilingScope` | no |  | `project`, `agent` |  | Which spend guardrails.dailyCostCeilingUsd is compared with. 'project' (the default, also when empty) compares it with the combined spend of all agents of the service process in the project, or in the caller's tenant on a multi-tenant project, so other agents' spend can exhaust this agent's ceiling. 'agent' keeps a ledger per agent (per tenant on a multi-tenant project) and compares the ceiling with this agent's own spend, calls in flight included. The refusal names the scope and the spend it counted. |
| `logPreviewChars` | `Integer` | no | `0` |  | min 0 | Redaction control for the tool-call AUDIT TRAIL (every tool execution logs an AgentToolCallAudit entry: who/what/tenant/cost/traceId). 0 (default) = WS2 posture: metadata and byte sizes only, no payload content. > 0 = include argument/result previews truncated to this many characters: every preview first goes through the framework log redaction (the request-log credential vocabulary, including tokens, client secrets, m2m and session-token names and credentials inside string values or plain text), then logMaskFields is masked; a preview that cannot be redacted is omitted. |
| `logMaskFields` | `String` | no |  |  |  | Comma-separated field names that are masked ('***') at ANY depth inside audit-trail previews when logPreviewChars > 0. Case-insensitive. Built-in always-masked names: password, token, secret, apiKey, authorization, accessToken. These masks are applied on top of the framework log redaction every preview already runs, so list only project-specific names. Example: 'ssn,cardNumber,iban'. |
| `allowedMimeTypes` | `String` | no |  |  |  | Comma-separated list of allowed MIME types for file uploads. Example: 'image/png,image/jpeg,image/webp' for vision agents. Each entry is an exact 'type/subtype', a family wildcard 'type/*' (so 'image/*' accepts every image subtype) or '*/*'; matching is case-insensitive and ignores ';' parameters, and any other shape fails generation naming the agent and the entry. Enforced by the upload manager. |
| `decisionGate` | [`AgentDecisionGate`](./AgentDecisionGate.md) | no |  |  |  | An optional calibrated decision gate over this agent's tool calls (AgentDecisionGate). Null = no gate, and the agent behaves exactly as before. Where `inputValidation` answers a question MScript can express about the whole request, this answers one it cannot about a single tool call - is this about to destroy something - and routes the call to deny, human approval, or a warning. |
| `requiredToolCalls` | `String` | no |  |  |  | Comma-separated list of TOOL names (as registered on the agent's tool registry - exact, case-sensitive) that MUST each have at least one SUCCESSFUL call in the run's own tool-call journal before the run may end 'success'. Enforced at the run FINISH path from the RUNTIME's journal (the per-run tool record persisted on sys_agentExecutions), never from the model's self-report: a run whose journal lacks a successful call to every listed tool ends 'failed' with an error naming ALL missing tools (code AGENT_REQUIRED_TOOL_NOT_CALLED). A call that returned an error, was rejected by a human approver, or was skipped does NOT satisfy the gate; a run that fails for any other reason keeps its own error (the gate only turns would-be successes into failures). Empty/absent = no mandated tools (default - nothing changes). Each entry must name a tool this agent's toolSettings actually registers (crud op names like 'create_order', apiTool names, invoke_agent_*, library/custom tool names, integration_* tools) - checked at design time (AGENT_REQUIRED_TOOL_NOT_REGISTERED). Use for agents whose job ends in a mandatory write: e.g. 'applyReplyAnalysis' on an agent whose entire purpose is that one write - the write skipped can no longer end green. |

## Constraints

Property rules:

- `costCeilingScope` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `maxToolCalls` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `maxTokenBudget` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `maxToolResultChars` must be at least 200. (`VALUE_OUT_OF_RANGE`)
- `elideToolResultsAfter` must be at least 0. (`VALUE_OUT_OF_RANGE`)
- `elideToolResultsOverChars` must be at least 0. (`VALUE_OUT_OF_RANGE`)
- `maxFileSizeMb` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `timeout` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `maxAgentDepth` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `dailyTokenBudgetPerUser` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `dailyCostCeilingUsd` must be at least 0. (`VALUE_OUT_OF_RANGE`)
- `logPreviewChars` must be at least 0. (`VALUE_OUT_OF_RANGE`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `AGENT_COST_CEILING_SCOPE_INERT` | warning | guardrails.costCeilingScope is 'agent' but guardrails.dailyCostCeilingUsd is not set, so there is no cost ceiling for the scope to apply to. |
| `AGENT_COST_CEILING_UNPRICED_MODEL` | warning | guardrails.dailyCostCeilingUsd is set but model "…" has no price entry: the cost governor will price it with the '*' fallback (…/… USD per 1M input/output tokens), so the ceiling may trip well below the real spend. |
| `AGENT_EVAL_WITHOUT_COST_CEILING` | warning | The agent declares … eval case(s) but no guardrails.dailyCostCeilingUsd. |
