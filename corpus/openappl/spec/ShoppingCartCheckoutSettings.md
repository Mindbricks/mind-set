# ShoppingCartCheckoutSettings

**Level:** `section` · **Family:** [ShoppingCartConfig](../ontology/families.md#shoppingcartconfig) (domain `Service`)

**Ontology:** [ShoppingCartCheckoutSettings in Part 1](../ontology/ShoppingCartCheckoutSettings.md)

Configuration for cart-to-order checkout process. Defines how checkout converts a cart into an order, including property mapping, order creation mode, and event publishing.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `orderCreationMode` | `OrderCreationMode` | no | `"local"` | `local`, `remote`, `none` |  | How to create orders from cart: 'local' creates order in same service, 'remote' publishes event for external order service, 'none' skips order creation. In 'local' mode the order row's money is the SERVER's checkout snapshot (a catalog-bound cart prices from the catalog; money keys in the request's checkoutData cannot move it), a settled cart becomes terminal ('convertedToOrder') and refuses further mutation, and a FAILED order create answers a typed 502 ORDER_CREATION_FAILED, publishes no checkout event, and leaves the cart retryable. A 'none'-mode cart still keeps server pricing from a bound catalog even though it creates no order. |
| `orderDataObjectName` | `String` | no | `null` |  |  | Name of the order DataObject in this service. Required when orderCreationMode is 'local'. The system will auto-detect if there's a DataObject with isOrder flag. |
| `autoMapProperties` | `Boolean` | no | `true` |  |  | Local mode only: in orderCreationMode 'remote' no order is built here and this has no effect (validation warning SHOPPING_CART_REMOTE_MODE_LOCAL_ONLY_SETTING when false there). If true, automatically copy the canonical cart fields onto the order payload. The full list is ownerId, currency, subtotal, discountTotal, vatTotal, grossTotal, total, couponCodes, redeemedPoints, pointsValue and appliedPointsValue, plus userId taken from the cart owner. Order properties the order DataObject does not declare are dropped (and logged), so declare the columns you want to keep. Note that total is NET of any loyalty redemption: to keep an order row whose total is reconstructable from its own columns, declare grossTotal and appliedPointsValue too, since total = grossTotal - appliedPointsValue. |
| `propertyMappings` | [`CartToOrderPropertyMapping`](./CartToOrderPropertyMapping.md)[] | no | `[]` |  |  | Override specific cart-to-order property mappings when autoMapProperties isn't sufficient. Local mode only: in orderCreationMode 'remote' the cart builds no order, so the mappings are not applied to the checkout event (validation warning SHOPPING_CART_REMOTE_MODE_LOCAL_ONLY_SETTING); map the order fields in the consuming service. |
| `orderDataClause` | [`MScript`](./MScript.md) | no | `null` |  | MScript kind `code` | Local mode only (in orderCreationMode 'remote' it has no effect: validation warning SHOPPING_CART_REMOTE_MODE_LOCAL_ONLY_SETTING). JavaScript injected into order creation for custom properties, written as an object-literal BODY (`prop: expr, prop: expr`) and merged onto the order payload last, so it outranks autoMapProperties, propertyMappings and initialOrderStatus. Exactly three bindings are in scope: the frozen cart as 'cart', its lines as 'cartItems', and the generated cart manager as 'this' - whose per-request context is 'this.userId', 'this.sessionId', 'this.clientId' and 'this.requestId'. The checkout request body is NOT in scope here; read it with a propertyMappings entry whose cartProperty is 'checkoutData.<field>'. A member that does not exist yields undefined rather than a value. Example: `{ "js": "salesChannel: 'web', referralCode: this.userId" }` |
| `publishCheckoutEvent` | `Boolean` | no | `false` |  |  | Whether to publish a checkout completed event to Kafka. Always true when orderCreationMode is 'remote'. |
| `checkoutEventTopic` | `String` | no | `null` |  |  | Kafka topic for checkout events. Default: '{serviceCodename}-cart-checkout-completed'. An explicit topic is PROJECT-SCOPED on the wire like a PublishEventAction topic: it is published as '<projectCodename>-<topic>', and a name that already starts with '<projectCodename>-' is left unchanged, so the preview and stage instances of one project never share it. A consumer in the project may name it with or without the prefix. The event carries { cartId, checkoutId, cart, items, rewards, orderId, orderCreationMode, checkoutData } under data (the unified event envelope, type '<cartObjectName>.checkoutCompleted'). |
| `initialOrderStatus` | `String` | no | `"pending"` |  |  | Initial status to set on created orders. Usually 'pending' or 'awaiting_payment'. Local mode only: in orderCreationMode 'remote' the consuming service sets the status (a non-default value there is the validation warning SHOPPING_CART_REMOTE_MODE_LOCAL_ONLY_SETTING). |
| `externalCheckoutConsumer` | `Boolean` | no | `false` |  |  | Declares that the order service consuming this cart's checkout topic lives OUTSIDE this project (another project, an external system). It only matters in orderCreationMode 'remote': a remote checkout publishes the checkout topic and creates no order itself, so design time requires an order-creating consumer of that exact topic - a create Business API whose controllers.kafkaSettings consumes it (requestTopicName) - and reports CART_CHECKOUT_TOPIC_NO_CONSUMER (ERROR) when the project has none. An event subscription, an event notification (a receipt mail), a kafka controller of another kind or an edge function on the topic creates no order and does not count. Set this flag to true to state that the consumer is external: the finding is then satisfied and the project validates and builds. Leave it false (the default) when the order service is part of this project. In 'local' and 'none' mode the flag is ignored (no finding, nothing emitted), and it never changes generated code in any mode. |

## Constraints

Property rules:

- `orderCreationMode` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- The items of `propertyMappings` must have distinct names (`cartProperty`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)
