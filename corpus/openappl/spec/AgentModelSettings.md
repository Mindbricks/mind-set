# AgentModelSettings

**Level:** `section` · **Family:** [AIAgent](../ontology/families.md#aiagent) (domain `Service`)

**Ontology:** [AgentModelSettings in Part 1](../ontology/AgentModelSettings.md)

AI provider and model configuration for the agent. Defines which LLM or generative model to use, its parameters, and optional dynamic system prompt sources that inject contextual data into the system message at runtime.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `providerName` | `String` | no |  |  | format [codeName](./value-formats.md#codename) | Reference to a project-level AI provider by codeName. Must match an entry in projectSettings.aiProvidersSettings.aiProviders[].name — the runtime looks up the provider's type + env-var-driven credentials from the per-service providers-manifest (codegen-emitted). This is the canonical (and only) provider binding: every agent must set providerName OR declare a customEndpoint section. A legacy raw `provider` type string (pre-aiProviders[] blueprints) is accepted and auto-migrated into providerName at validation time. The referenced provider's family must match the agent's modality (LLM for text/vision, image/audio/video providers for media agents). |
| `model` | `String` | yes |  |  |  | Provider-specific model name. Current latest model IDs (as of mid-2026): Anthropic — 'claude-opus-4-8' (most capable), 'claude-sonnet-5' (balanced default), 'claude-haiku-4-5' (fast). OpenAI — 'gpt-5', 'gpt-5-mini'. Google — 'gemini-2.5-pro', 'gemini-2.5-flash'. Image — 'dall-e-3' (OpenAI), 'flux-pro' (fal). Audio TTS — 'eleven_multilingual_v2' (ElevenLabs). Always pick the latest model from the provider's docs unless the project explicitly requires an older version — older Claude IDs like 'claude-sonnet-4-6', 'claude-sonnet-4-5' or 'claude-3-5-sonnet-...' are out of date. |
| `systemPrompt` | `Text` | no |  |  |  | Static system instructions that define the agent's persona, constraints, and output format. This text is sent as the system message in every request. |
| `temperature` | `Double` | no |  |  | min 0, max 2 | Controls randomness in model output. Range 0.0-2.0 (anthropic/bedrock providers accept 0.0-1.0 — validated against the bound provider). Lower values (0.1-0.3) for deterministic tasks, higher values (0.7-1.0) for creative tasks. Default: 0.7. |
| `maxTokens` | `Integer` | no |  |  | min 1 | Maximum number of output tokens per model call (thinking tokens count against it). Leave null for the provider default (Anthropic: model-aware, 16384 on current Claude models, 8192 on Claude 3.5, 4096 on the Claude 3 base models and on a non-Claude model id behind a custom Anthropic-format endpoint). On Anthropic models thinking is off unless reasoningEffort is set; with an effort on Sonnet 5 / Opus 4.6+ the limit covers thinking AND the answer (no separate budget exists there), so give it room (16000 or more for tool-heavy chat agents). A final turn that spends the whole limit on thinking is retried once with thinking off before it fails with AGENT_EMPTY_OUTPUT. |
| `responseFormat` | `AgentResponseFormat` | no |  | `text`, `json`, `url`, `binary` |  | Expected response format: 'text' for plain text, 'json' for structured JSON, 'url' for media URLs, 'binary' for raw binary data. 'json' is wired for EVERY provider family: providers with a native JSON/structured-output mode (openai-compatible, anthropic current-gen, google) receive it natively; the rest get prompt-based emulation with a bounded validate-and-repair loop. Pair with responseSchema to enforce a specific JSON shape. |
| `fallbackProviders` | `String` | no |  |  |  | Comma-separated ordered list of project-level AI provider names (aiProvidersSettings.aiProviders[].name) to fall back to when the primary provider fails with a retryable error (429 rate-limit, 5xx, network) after its retry budget is exhausted. The conversation is provider-neutral, so history carries over losslessly to the next provider in the chain. Each entry is existence- and family-checked at design time. Example: 'backupOpenai,localOllama'. |
| `responseSchema` | `Text` | no |  |  |  | JSON Schema (as a JSON string) that the agent's final response must validate against. Implies JSON output. Providers with native structured output (openai-compatible json_schema, anthropic current-gen output_config, google responseSchema) receive the schema natively; other providers get a schema instruction in the system prompt. Either way the runtime validates the final answer and runs a bounded repair loop (validation errors are fed back to the model) before failing. Object-root schemas only. An EMPTY schema ('{}', or an object schema that declares no property) means NO structured output: it is never sent to the provider (anthropic refuses it), the agent falls back to its responseFormat, and validation warns (AGENT_RESPONSE_SCHEMA_EMPTY). Provider schema limits: anthropic compiles the schema into a decoding grammar and documents at most 24 optional properties (not listed in required) and 16 union-typed properties (anyOf / oneOf or a type array) across a request's strict schemas, plus an internal grammar-size limit ('Schema is too complex for compilation'); validation warns when an agent bound to an anthropic provider exceeds the two counts (AGENT_RESPONSE_SCHEMA_TOO_COMPLEX). When the provider refuses the schema as too complex to compile, the runtime retries that call ONCE in JSON mode: the schema rides the system prompt instead of the wire, native enforcement stays off for that provider instance from then on, and the answer is validated locally by the same repair loop (a still-invalid answer fails naming the fallback). Prefer required fields and flat structures. Example: '{"type":"object","properties":{"sentiment":{"type":"string","enum":["pos","neg"]}},"required":["sentiment"]}'. |
| `strictOutput` | `Boolean` | no | `true` |  |  | Controls what happens when structured output (responseFormat 'json' and/or responseSchema) still fails validation after the bounded repair loop. true (default): the run fails with a clean validation error — the caller NEVER receives schema-violating raw text. false: the raw text is returned with a logged warning (legacy fail-open behavior). |
| `toolChoice` | `String` | no |  |  |  | Controls how the model may use tools on the first call of a run: 'auto' (default — model decides), 'any' (model MUST call some tool), 'none' (tool calling disabled), or the exact name of a tool the model MUST call. Mapped to each provider's native control (openai tool_choice, anthropic tool_choice, google functionCallingConfig.mode, bedrock toolConfig.toolChoice). |
| `parallelToolCalls` | `Boolean` | no | `true` |  |  | When false, the model is instructed to issue at most ONE tool call per assistant turn (openai parallel_tool_calls:false, anthropic disable_parallel_tool_use). Default: true (parallel tool calls allowed). Providers without a native control ignore this. |
| `contextWindowTokens` | `Integer` | no |  |  | min 1024 | Override of the model's context-window size (in tokens) used by the runtime's context compaction — when the estimated conversation size approaches this window, older turns are compacted (sliding window or summarization per chatSettings). Leave null to use the provider family's default estimate. |
| `reasoningEffort` | `AgentReasoningEffort` | no | `null` | `none`, `minimal`, `low`, `medium`, `high` |  | Reasoning effort: 'none', 'minimal', 'low', 'medium' or 'high'. OpenAI-family reasoning models (o-series, gpt-5 family) receive it as reasoning_effort. Anthropic models receive it as thinking configuration: adaptive thinking with output_config.effort on current models, a budget_tokens clamped below maxTokens on older ones; unset or 'none' turns thinking off where the model allows it. Other providers ignore it. Leave null for no thinking on Anthropic and the model's own default elsewhere. On a gpt-5 family model whose default effort rejects function tools on chat/completions, a tool-bearing request that the provider refuses for that reason is resent once with reasoning_effort 'none' when this field is null; set it explicitly to choose the effort yourself. Not every model accepts every value (older gpt-5 models do not accept 'none'). |
| `systemPromptSources` | [`AgentContextSource`](./AgentContextSource.md)[] | no |  |  |  | Dynamic data sources fetched at runtime and injected into the system prompt as named context segments (appended under a '## Context' block, one segment per source). Refresh semantics: the whole system message pipeline is built once per runtime instance unless chatSettings.refreshSystemPrompt is true (re-evaluated every turn); each source may additionally cache its fetched value for cacheTtlSeconds. A source that fails to fetch is FAIL-SOFT: the run continues without that segment (logged warning). Useful for injecting user profiles, configuration, or domain knowledge. |

## Constraints

Property rules:

- `model` must be present. (`REQUIRED_FIELD_MISSING`)
- `responseFormat`, `reasoningEffort` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `providerName` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)
- `temperature` must be between 0 and 2. (`VALUE_OUT_OF_RANGE`)
- `maxTokens` must be at least 1. (`VALUE_OUT_OF_RANGE`)
- `contextWindowTokens` must be at least 1024. (`VALUE_OUT_OF_RANGE`)
- The items of `systemPromptSources` must have distinct names (`name`, compared case-insensitively). (`DUPLICATE_ASSET_NAME`)

Pattern rules:

| Code | Severity | Rule |
| --- | --- | --- |
| `DUPLICATE_FALLBACK_PROVIDER` | warning | Provider "…" appears more than once in fallbackProviders — duplicates are redundant. |
| `FALLBACK_IS_PRIMARY_PROVIDER` | warning | Provider "…" is already the primary providerName — listing it as a fallback retries the same provider. |
| `INVALID_TOOL_CHOICE` | error | toolChoice must be 'auto', 'any', 'none', or a specific tool name (codeName) — got "…". |
| `LEGACY_AGENT_PROVIDER_FIELD` | warning | The raw "provider" type string is legacy — agents bind to a project-level AI provider via providerName. |
