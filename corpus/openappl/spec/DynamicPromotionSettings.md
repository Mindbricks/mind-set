# DynamicPromotionSettings

**Level:** `subsection` · **Family:** [ShoppingCartConfig](../ontology/families.md#shoppingcartconfig) (domain `Service`)

**Ontology:** [DynamicPromotionSettings in Part 1](../ontology/DynamicPromotionSettings.md)

Configuration for complex, database-driven promotions evaluated by the Promotion Engine at runtime. When enabled, the service gets ONE promotion DataObject, the campaign store {cartObjectName}Campaign (e.g. cartCampaign), and the generated cart manager loads its enabled rows into the engine. The loader contract: it reads rows with the query { isEnabled: true } and maps the columns name, priority, exclusive, stackable, requiresCoupon, couponCode, rules ([{ ruleType, config }]) and rewards ([{ rewardType, config }]) onto the engine, plus usageCount, the usage counter a usageLimit rule reads. There is NO Coupon object and NO CampaignUsage / UsageLog object: a coupon is the couponCode of a campaign row whose requiresCoupon is true, and usage is the usageCount column of the same row. A service may author {cartObjectName}Campaign itself (the authored object replaces the generated one), but it must then declare isEnabled, rules and rewards (validation ERROR SHOPPING_CART_CAMPAIGN_STORE_SHAPE otherwise, because the loader would read an empty catalog) and should declare couponCode and requiresCoupon (WARNING SHOPPING_CART_CAMPAIGN_STORE_COUPON_COLUMNS: without them no coupon can match).

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `enabled` | `Boolean` | no | `false` |  |  | Whether dynamic promotions are enabled. Generates the {cartObjectName}Campaign store (the only promotion DataObject) and wires the promotion engine to it. Every designer-authored surface on the store is operator-only: in a multi-tenant project restricted to the platform operator (superAdmin / saasAdmin; CART_CAMPAIGN_WRITE_NOT_PLATFORM_OPERATOR / CART_CAMPAIGN_READ_NOT_PLATFORM_OPERATOR), in a single-tenant project to the campaign operator the generated /campaigns routes admit (checkRoles of superAdmin / admin / saasAdmin / tenantOwner / tenantAdmin only, loginRequired true, M2MAllowed false; CART_CAMPAIGN_WRITE_NOT_CAMPAIGN_OPERATOR / CART_CAMPAIGN_READ_NOT_CAMPAIGN_OPERATOR) - a create / update / delete or get / list api on the store, a crud or read action on it in any api, an internal call, an api serving a DataView that reads it, and an event notification bound to such a view. All four codes are non-bypassable. |
| `supportCoupons` | `Boolean` | no | `false` |  |  | Whether the cart takes coupon codes: emits the cart router's POST /<cart>/coupons and DELETE /<cart>/coupons/:code routes. No Coupon DataObject is generated: a coupon is a campaign row with requiresCoupon true and its couponCode. Runtime verdicts on the coupon routes are typed: applying an UNKNOWN code answers 404 COUPON_NOT_FOUND; a code whose campaign matched but whose rules refuse the cart (expired window, minimums, usage caps) answers 400 COUPON_NOT_ELIGIBLE - it is never silently 'applied' with a zero discount. Removing one coupon re-evaluates every remaining applied code, so the surviving coupons keep their discounts. |
| `supportMultipleCoupons` | `Boolean` | no | `false` |  |  | Declared permission for multiple coupon codes, default false. Current nodejs coupon processing can accept multiple codes even with false or unset. Explicit true enables the separately configured maxCouponsPerCart cap; that gate does not implement a one-coupon restriction for false. Default behavior and migration remain undecided. |
| `maxCouponsPerCart` | `Integer` | no | `null` |  |  | Nodejs maximum distinct accepted coupon codes when dynamic promotions and supportMultipleCoupons are enabled. Null is unlimited; zero accepts none. Reapplying a code does not consume another slot. Admission and every reprice enforce the cap, including fresh-header CAS retries and BusinessApi cart actions. Before candidate evaluation and counting, validation and mutation reprice the other stored codes against current enabled, eligible campaigns; withdrawn or ineligible codes consume no slot. Read-only validation does not write the normalized basket. This cap does not enforce a one-coupon restriction when supportMultipleCoupons is false. |
| `campaignSettings` | [`AutoGeneratedCampaignSettings`](./AutoGeneratedCampaignSettings.md) | yes |  |  |  | Configuration for the auto-generated Campaign DataObject. |
| `cacheSettings` | [`PromotionCacheSettings`](./PromotionCacheSettings.md) | yes |  |  |  | Redis caching settings for campaign data. |

## Constraints

Property rules:

- `campaignSettings`, `cacheSettings` must be present. (`REQUIRED_FIELD_MISSING`)
