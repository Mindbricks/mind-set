# RemoteBucketStorage

**Level:** `section` · **Family:** [RemoteBucket](../ontology/families.md#remotebucket) (domain `Service`)

**Ontology:** [RemoteBucketStorage in Part 1](../ontology/RemoteBucketStorage.md)

Storage configuration for the remote bucket. Selects which named project bucketProvider to use, the (optional) physical bucket override, and how download URLs are generated. For object storage without a project bucketProvider, prefer NativeBucket with NativeBucketStorage: the hosting platform manages the store.

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `providerName` | `String` | yes |  |  |  | Name of the project-level bucketProvider that holds this bucket's credentials and defaults (configured under projectSettings.bucketProvidersSettings.bucketProviders). The service reads its config from BUCKET_<NAME>_* environment variables at runtime. |
| `remoteBucketName` | `String` | no |  |  |  | Optional override for the physical bucket name at the provider. If null, falls back to the bucketProvider's `defaultBucketName`. The bucket must already exist at the provider — it is not auto-created. Names are checked against the bound provider: s3 uses 3-63 lowercase letters, digits, dots and hyphens, begins and ends alphanumeric, rejects adjacent dots, IP-shaped names and reserved prefixes/suffixes (including xn-- and -s3alias); r2 uses 3-63 lowercase letters, digits and hyphens with alphanumeric ends; gcs allows lowercase letters, digits, dots, underscores and hyphens, alphanumeric ends, 3-63 characters without dots or up to 222 with 1-63-character components, and rejects IP-shaped and Google-reserved names; azure uses 3-63 lowercase letters, digits and hyphens with alphanumeric ends and no consecutive hyphens (the reserved containers $root, $web and $logs are allowed). Violations are BUCKET_NAME_INVALID errors, except s3Compatible receives warnings. The exact REPLACE_ME placeholder is a BUCKET_NAME_PLACEHOLDER warning. A RemoteBucket with no effective override or provider default is a REMOTE_BUCKET_NAME_EMPTY error. See the bucket-providers integration guide for details. |
| `keyPrefix` | `String` | no |  |  |  | Optional path prefix added to every stored object key (e.g., 'avatars/' produces keys like 'avatars/{uuid}'). Useful when multiple buckets share a single physical provider bucket. |
| `presignTTLSeconds` | `Integer` | no | `900` |  |  | Lifetime of a presigned URL in seconds. Default 900 (15 minutes). Downloads are always served as a short-lived presigned URL — the service authorizes the request, then the client fetches directly from the storage provider. A presigned URL is a BEARER credential — anyone holding it can fetch the object until it expires, and it CANNOT be revoked early — so the TTL is the exposure window if the URL leaks (logs, Referer headers, shared links). 15 minutes is the common industry range for user-facing downloads. Note a short TTL does NOT truncate large downloads: the signature is checked when the request STARTS, so a transfer that begins before expiry completes normally. Raise it only for batch or machine consumers that hold a URL before using it. |
| `serverSideEncryption` | `Boolean` | no | `false` |  |  | When true, enables server-side encryption at the provider (SSE-S3 for AWS, default encryption for GCS/Azure) by signing `x-amz-server-side-encryption: AES256` into every upload. Default: false - SSE is OPT-IN. An S3-compatible store with no SSE-S3 key configured (SeaweedFS's default posture, some MinIO builds) answers 500 InternalError to a PUT carrying that header, and because CreateBucket/HeadBucket never touch SSE the failure only surfaces at the first upload. Turn it on when the target store is known to accept SSE-S3 (AWS S3 always does); GCS and Azure encrypt at rest regardless and ignore the flag. |
| `objectCacheControl` | `String` | no | `null` |  |  | Cache-Control this bucket's objects are stored and served with. Null (the default) means the framework value `public, max-age=31536000, immutable`, which is right for content-addressed assets and wrong for a bucket that holds mutable documents: set for example `no-cache` for a rendered report rewritten in place through the SDK, `private, max-age=60` for a regulated bucket, `public, max-age=300` for a scratch area. The value is set on BOTH sides of the round trip - the stored object metadata (S3 `CacheControl`, GCS `metadata.cacheControl`, Azure `blobCacheControl`) and the `Cache-Control` entry of the `headers` map the presigned upload returns, plus the signed GET-side response override on S3 (`ResponseCacheControl`) and Azure (`rscc`) - because the read-time override wins over what is stored. GCS has NO cache-control response override (measured), so on GCS the stored value is the only carrier: changing this field applies to objects written AFTER the change and NEVER retroactively to objects already in the bucket. Must be a plausible Cache-Control token list (comma-separated `directive` or `directive=value`); a malformed value is an authoring-time error, because every provider stores the string verbatim and then serves it to every browser. |
| `delivery` | `RemoteBucketDelivery` | no | `"presigned"` | `presigned`, `public` |  | How GET /bucket/{name}/download/:key hands out the bytes. 'presigned' (the default) authorizes the request and answers 302 with a fresh short-lived presigned URL and Cache-Control: no-store, because that URL is a bearer credential. 'public' is for a bucket that holds PUBLIC CONTENT only (catalog covers, product images): the route answers 302 to the object's STABLE URL under publicBaseUrl, cacheable with the bucket's object Cache-Control, so browsers and CDNs reuse the bytes across visits; the upload response also returns that URL as publicUrl. A public bucket offers NO presigned upload: POST /bucket/{name}/upload-url answers 405 PRESIGNED_UPLOAD_NOT_OFFERED, because a presigned PUT binds no Content-Type and its body could be served as stored from the public URL; every upload goes through the classifying POST /bucket/{name}/upload. The objects must be publicly readable at the provider (a bucket policy granting read on this bucket's keyPrefix, or a CDN in front of it); the platform does not change provider policies. 'public' is accepted only for a bucket declared as public content, otherwise the design is refused (REMOTE_BUCKET_PUBLIC_DELIVERY_*): bucketAuthorization.readAccess 'public', no readAuthScript, enableKeyAccess off, ownerDataObject.downloadRequiresActiveOwner off, publicBaseUrl set, bucketBasics.allowedMimeTypes declared and listing no active type (HTML, XHTML, SVG, JavaScript, XML), and virusScanMode 'block' (a quarantined object must never sit behind a public URL). An object whose key names an active type is still served through an inert presigned URL. Generated by the nodejs, java, dotnet and python lanes; the other languages keep presigning (warning REMOTE_BUCKET_PUBLIC_DELIVERY_NOT_PORTED). |
| `publicBaseUrl` | `String` | no | `null` |  |  | The https URL that maps to the ROOT of the physical bucket when delivery is 'public': the S3 virtual-hosted URL (https://<bucket>.s3.<region>.amazonaws.com), the GCS or Azure container URL, or a CDN / custom domain in front of it. The download route appends the full storage key (keyPrefix included, each segment URL-encoded): a key catalog/book-covers/abc.webp under https://cdn.example.com is served from https://cdn.example.com/catalog/book-covers/abc.webp. Must be an absolute https URL with no query string or fragment; a trailing slash is ignored. Required when delivery is 'public', ignored otherwise. Do not use a subdomain of the application's own domain: the storage origin serves user uploads. |

## Constraints

Property rules:

- `providerName` must be present. (`REQUIRED_FIELD_MISSING`)
- `delivery` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
