# Provider catalog: fiscalProvider

Entries of this family are written with [`FiscalProvider`](../FiscalProvider.md); the keys below are what an entry's `configuration` takes, per `provider` brand.

Turkey-first roster (Faz 3a shape; Faz 3d adapters: wave 1 elogo/foriba/nilvera, wave 2 izibiz/uyumsoft). Key names were verified against the integrators' documented credential models when each adapter shipped, and every endpoint/field name lives in the adapter's VERIFY-marked constants block - a vendor-side rename is a catalog/adapter edit, not a schema break. All brands are NATIVE (no bridge family): fiscal integrators are SaaS APIs and carry their credentials here.

## Environment names

| Prefix | Key style |
|---|---|
| `FISCAL_PROVIDER` | `upperSnake` |

The key style `upperSnake` turns a camelCase key into UPPER_SNAKE; `verbatim` keeps it as written.

|---|---|---|---|---|---|---|---|
| `username` | string | yes | yes |  |  |  | eLogo API account username. Treated as a secret: paired with the password it is a full credential set. |

Ops-supplied here beside the credentials that select the account, and emitted as FISCAL_PROVIDER_<NAME>_SELLER_TAX_ID, because it is ENVIRONMENT-VARYING: a sandbox integrator account carries a different tax id than production, and the seller id must equal the authenticated account's own. | `sellerDistrict` | string |  |  |  |  |  | The PROJECT's own registered district (Turkey: ilçe) for the documents this integrator account issues - UBL-TR makes cbc:CitySubdivisionName a MANDATORY PostalAddress member (Uyumsoft's schema validation refused a document without it), so the builder falls back to a documented generic default ('Merkez') when this is unset. Emitted as FISCAL_PROVIDER_<NAME>_SELLER_DISTRICT. Not a secret. Set the real ilçe for production documents. |
| `sellerCity` | string |  |  |  |  |  | The PROJECT's own registered city/province (Turkey: il) for the documents this integrator account issues - UBL-TR makes cbc:CityName a MANDATORY PostalAddress member, so the builder falls back to the party's country context when this is unset. Emitted as FISCAL_PROVIDER_<NAME>_SELLER_CITY. Not a secret. Set the real il for production documents. |
| `serialPrefix` | string |  |  |  |  |  | The 3-uppercase-letter GIB document serial prefix of the e-Arsiv series. TR fiscal documents must carry cbc:ID as a GIB DOCUMENT SERIAL - prefix + 4-digit issue year + 9-digit zero-padded sequence (e.g. ABC2026000000001) - allocated by the fiscal layer at prepare time from the sys_fiscalSerialSequence counter (one counter per prefix) and REUSED on resubmit; the app-side invoice number is correlation data (an AdditionalDocumentReference), never the wire id. GIB keeps e-Fatura and e-Arsiv on SEPARATE series: TR_EARSIV documents draw from serialPrefix, TR_EFATURA documents from eInvoiceSerialPrefix, and the two must differ. REQUIRED for e-Arsiv routes: a TR_EARSIV submission without a valid serialPrefix is refused with a typed 400 naming this key BEFORE any vendor call. Validated [A-Z]{3}. Emitted as FISCAL_PROVIDER_<NAME>_SERIAL_PREFIX. Not a secret. |
| `serialSequenceStart` | number |  |  |  |  |  | The FLOOR of the GIB wire-serial sequence: the first 9-digit sequence number this service may issue under serialPrefix, for an integrator account whose prefix already issued numbers outside this service's own sys_fiscalSerialSequence counter (a migrated account, or a service moved onto a new provider entry). Honoured on every allocation as next = max(lastNumber, serialSequenceStart - 1) + 1, so a fresh counter starts AT this number and a counter already past it just continues; it never lowers a counter and never changes a document that already carries its serial (the burn-and-advance resubmit is unchanged). A whole number from 1 to 999999999; any other value is refused at submission with a typed 400 naming this key, before any vendor call. Optional - unset means the series starts at 1. It does NOT make two services on one provider entry safe (that shape stays the FISCAL_SERIAL_NAMESPACE_SHARED design-time error). Scope it to one year with serialSequenceStartYear: the floor exists because that year's numbers were already issued outside the counter, so with the year set it applies ONLY to that year's serials and every other year starts at 1; without the year it applies every year, so a new year's series starts at the floor again (a design-time WARNING says so). Emitted as FISCAL_PROVIDER_<NAME>_SERIAL_SEQUENCE_START. Not a secret. |
| `serialSequenceStartYear` | number |  |  |  |  |  | The 4-digit YEAR the serialSequenceStart floor belongs to. A floor exists because that year's serials were already issued outside this service's counter (a migrated account); with the year set, the floor applies ONLY to allocations whose serial year (the Turkey-local issue year, the year inside the serial) equals it, and every other year's series starts at 1. Unset, the floor applies every year, so each January the new year's series starts at the floor again. Anything but a 4-digit year is refused at submission with a typed 400 naming this key, before any vendor call. Emitted as FISCAL_PROVIDER_<NAME>_SERIAL_SEQUENCE_START_YEAR. Not a secret. |
| `eInvoiceSerialPrefix` | string |  |  |  |  |  | The 3-uppercase-letter GIB document serial prefix of the e-Fatura series. GIB keeps e-Fatura and e-Arsiv on SEPARATE series, each consecutive on its own, so a TR_EFATURA document (a buyer registered on the e-Fatura network) draws its cbc:ID serial - prefix + 4-digit issue year + 9-digit zero-padded sequence - from this prefix and its own sys_fiscalSerialSequence counter, while TR_EARSIV keeps serialPrefix. Register the series with the integrator first (the account must know a series before a document may carry it). Must differ from serialPrefix: an equal value is refused at design time (FISCAL_SERIAL_NAMESPACE_SHARED) and at submission (typed 400). REQUIRED for e-Fatura routes: a TR_EFATURA submission without a valid eInvoiceSerialPrefix is refused with a typed 400 naming this key BEFORE any vendor call. A resubmit of the same scheme reuses the document's serial; a resubmit whose scheme changed (e-Arsiv refused, then e-Fatura) takes a fresh serial from the new scheme's series. Validated [A-Z]{3}. Emitted as FISCAL_PROVIDER_<NAME>_E_INVOICE_SERIAL_PREFIX. Not a secret. |
| `eInvoiceSerialSequenceStart` | number |  |  |  |  |  | The FLOOR of the e-Fatura series (eInvoiceSerialPrefix): the first 9-digit sequence number this service may issue under eInvoiceSerialPrefix, with the same contract as serialSequenceStart - next = max(lastNumber, eInvoiceSerialSequenceStart - 1) + 1, a whole number from 1 to 999999999, refused at submission with a typed 400 naming this key otherwise. Optional - unset means the e-Fatura series starts at 1. Scope it to one year with eInvoiceSerialSequenceStartYear (the same rule as serialSequenceStartYear, independently of it). Emitted as FISCAL_PROVIDER_<NAME>_E_INVOICE_SERIAL_SEQUENCE_START. Not a secret. |
| `eInvoiceSerialSequenceStartYear` | number |  |  |  |  |  | The 4-digit YEAR the eInvoiceSerialSequenceStart floor belongs to - the same rule as serialSequenceStartYear, for the e-Fatura series and independent of it. Emitted as FISCAL_PROVIDER_<NAME>_E_INVOICE_SERIAL_SEQUENCE_START_YEAR. Not a secret. |
| `serialAssignment` | enum |  |  | `platform` | `platform`, `vendor` |  | Who numbers this entry's fiscal documents. "platform" (the default; unset means the same): the fiscal layer allocates the GIB serial (cbc:ID) from its own sys_fiscalSerialSequence counter, with serialPrefix / eInvoiceSerialPrefix and the serialSequenceStart floors. "vendor": the INTEGRATOR numbers each document when it accepts the submission - supported by uyumsoft only (and simulated by mock); any other brand is a design-time ERROR (FISCAL_SERIAL_ASSIGNMENT_UNSUPPORTED) and a typed 400 at submission. In vendor mode the platform keeps no counter for the entry: cbc:ID carries only the series prefix (eInvoiceSerialPrefix for e-Fatura, serialPrefix for e-Arsiv; empty when unset, which numbers from the integrator account's default series), the ETTN (cbc:UUID) and LocalDocumentId are still the platform's and stay the same across re-sends, and the number the integrator answers is written to the fiscal document's documentSerial (null until it is known; recovered from the outbox when the answer was lost). A synchronous refusal consumes no number, so the series stays gapless except for a document the integrator numbered and GIB later refused. The serialSequenceStart floors do not apply (WARNING FISCAL_SERIAL_ASSIGNMENT_VENDOR_IGNORES_FLOOR when set). Operational rules: never mix explicit (platform) and vendor numbering in one series - the integrator's counter does not skip explicitly issued numbers and the series then refuses every document (FISCAL_VENDOR_SERIAL_CONFLICT); a series moved from platform numbering needs its counter at the integrator set past the highest issued number first (or a fresh prefix); a prefix must be defined for the account in the integrator's portal first (Uyumsoft: Ayarlar > Fatura Seri Tanimlari) - an undefined prefix is not refused, the integrator silently numbers from the default series (logged as FISCAL_VENDOR_SERIAL_PREFIX_MISMATCH). Emitted as FISCAL_PROVIDER_<NAME>_SERIAL_ASSIGNMENT. Not a secret. |
| `vatExemptionReasonCode` | string |  |  |  |  |  | GIB KDV exemption reason CODE for zero-amount VAT buckets: the schematron requires cbc:TaxExemptionReasonCode + cbc:TaxExemptionReason on every 0015 KDV bucket whose tax amount is 0, at the line-level and document-level TaxTotals alike. Optional - when unset the document builder applies the documented generic default 350 (the KDV exemption list's generic bucket, 'Diğerleri'). This is the PROVIDER-WIDE fallback: a line's own code (InvoiceLineRelation.vatExemptionCodeProperty) wins for that line. Set the real exemption code when the project's zero VAT has a specific legal basis; an exemption code (2xx/3xx, 350 included) makes the document ISTISNA, while 351 (a 0% line that is NOT exempt) keeps SATIS. A value that is not a 3-digit GIB code is a design-time WARNING. Emitted as FISCAL_PROVIDER_<NAME>_VAT_EXEMPTION_REASON_CODE. Not a secret. |
| `vatExemptionReason` | string |  |  |  |  |  | GIB KDV exemption reason TEXT paired with vatExemptionReasonCode, stamped on the same zero-amount 0015 buckets. Optional - when unset the document builder writes the official GIB text of the resolved code (350: 'Diğerleri'); must be non-empty on the wire (the schematron refuses a blank reason). It pairs ONLY with this entry's own vatExemptionReasonCode: a line or invoice that names its own code gets that code's official text. Emitted as FISCAL_PROVIDER_<NAME>_VAT_EXEMPTION_REASON. Not a secret. |
