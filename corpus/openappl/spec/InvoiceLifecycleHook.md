# InvoiceLifecycleHook

**Level:** `subsection` · **Family:** [ObjectSettings](../ontology/families.md#objectsettings) (domain `DataObject`)

**Ontology:** [InvoiceLifecycleHook in Part 1](../ontology/InvoiceLifecycleHook.md)

**Name:** an instance is named by `name`.

A designer-authored MScript handler fired by the invoice dispatcher when the invoice state machine advances. Mirrors the payment LifecycleHook shape (name / trigger / condition / script) but carries its OWN trigger vocabulary — the payment PaymentLifecycleTrigger enum is reconciled 1:1 with the payment lifecycle machines and deliberately stays untouched by the invoice family. Hooks run after the FSM transition is persisted; a failure inside a hook does not roll back the transition. The hook context is the NORMALIZED document, not a ledger row: `invoice` is a NormalizedInvoiceDetail on every trigger, `allocation` (NormalizedPaymentApplication) and `creditNote` (NormalizedCreditNote) are set only on their own triggers - see `script` for every field and for where the source row id lives. A member read those shapes do not carry is reported at design time (INVOICE_LIFECYCLE_HOOK_UNKNOWN_FIELD_SILENT, WARNING), as is a read on a root the trigger never supplies (INVOICE_LIFECYCLE_HOOK_ROOT_NULL_ON_TRIGGER, WARNING).

## Properties

| Name | Type | Required | Default | Allowed values | Details | Description |
| --- | --- | --- | --- | --- | --- | --- |
| `name` | `String` | yes |  |  | format [codeName](./value-formats.md#codename) | Unique name of this hook within its parent InvoicingConfig. Used in logs and the events table. |
| `trigger` | `InvoiceLifecycleTrigger` | yes |  | `afterInvoiceFinalized`, `afterInvoicePaid`, `afterInvoicePartiallyPaid`, `afterInvoiceVoided`, `afterInvoiceUncollectible`, `afterCreditNoteIssued`, `afterPaymentApplied` |  | Which invoice lifecycle event fires this hook. |
| `description` | `Text` | no |  |  |  | Human-readable explanation of what this hook does. |
| `condition` | [`MScript`](./MScript.md) | no |  |  | MScript kind `code` | Optional MScript boolean - when present and falsy, the hook is skipped for this event. Sees the same names as `script` (`invoice`, `allocation`, `creditNote` - the normalized shapes, not ledger rows) and is checked for field reads the same way. `this` is the generated `_hookCtx` whose only keys are those three names: `this.total` reads `undefined` (write `invoice.total`), and validation warns on it (LIFECYCLE_HOOK_THIS_NOT_IN_CONTEXT). |
| `script` | [`MScript`](./MScript.md) | yes |  |  | MScript kind `code` | MScript body executed when the trigger fires. Runs from the invoice dispatcher, not from a request - there is no request, session or user in scope. The names in scope are the NORMALIZED provider shapes, NOT the sys_<X>Invoice row. `invoice` is a NormalizedInvoiceDetail on every trigger: providerInvoiceId, invoiceNumber, series, statusLiteral, currency, subtotal, vatTotal, total, amountPaid, amountRemaining, dueDate, issuedAt, buyer, seller, lines, vatExemptionReasonCode, vatExemptionReason, metadata - and nothing else: it has NO `id`, `sourceObjectId` or `customerId`. The sys_<X>Invoice row id is `invoice.providerInvoiceId` (on every provider binding - an external provider's own invoice id rides `invoice.metadata.__externalInvoiceId`). The SOURCE row id is `invoice.metadata.sourceObjectId` and its object name `invoice.metadata.sourceObject`; the invoicing object's own row (the one the statusProperty mirror writes) is `invoice.metadata.__surfaceRowId`, equal to the source row id when the object invoices its own rows; the buyer is `invoice.buyer?.partyId`. The framework stamps those metadata keys when it creates the draft, so an invoice created provider-side and imported without them carries none - guard the read. `allocation` is a NormalizedPaymentApplication (providerAllocationId, providerInvoiceId, amount, currency, appliedAt, paymentRef, invoiceStatus, amountPaid, amountRemaining, metadata) on afterPaymentApplied / afterInvoicePaid / afterInvoicePartiallyPaid when the payment was applied in-process, and `null` otherwise - including an external provider's invoice.paid webhook. `creditNote` is a NormalizedCreditNote (providerCreditNoteId, providerInvoiceId, amount, currency, reason, issuedAt, metadata) on afterCreditNoteIssued and `null` on every other trigger. The generated file binds these names through `any`, so a field that is not on the lists above compiles and reads `undefined` at every fire - and an `undefined` handed on as an api id or where-clause value finds no row; validation reports such a read (INVOICE_LIFECYCLE_HOOK_UNKNOWN_FIELD_SILENT, WARNING - the binding is `any`, so the build does not break) whether it is a direct member (`invoice.x`, `invoice?.x`, `this.invoice.x`), a string-literal key (`invoice['x']`), a key destructured off the root (`const { x } = invoice`) or one of those through ONE alias level (`const inv = invoice`, `((inv) => ...)(invoice)`). A field an earlier hook assigns onto `invoice` excuses the read only when that hook has the SAME trigger and comes EARLIER in the list. Names are resolved by scope: a parameter or local that reuses the root's or an alias's name is that local, so neither its reads nor its writes count. Lexical identity is respected in parameter defaults, switch discriminants, named classes and static blocks; this is not general dataflow analysis. Not checked (silence is not clean): a key computed at runtime, a spread or rest element, a `let` alias, an alias of an alias, a root renamed while destructuring `this`, a `this` rebound by a nested non-arrow `function`, and a root handed to any function other than an inline IIFE. Reach service logic through `LIB.<module>(...)` and other rows through `API.<apiName>(...)` (Node.js only: dotnet generation refuses an `API` read in invoice hook slots, use `LIB`) - the generated hook file does not import the dbLayer getters. Use hooks to fan out to other services (publish kafka events), update related records, or run application-side bookkeeping. Example: `await API.markOrderInvoiced({ orderId: invoice.metadata?.sourceObjectId, invoiceNumber: invoice.invoiceNumber })`. |

## Constraints

Property rules:

- `name`, `trigger`, `script` must be present. (`REQUIRED_FIELD_MISSING`)
- `trigger` must be one of the allowed values (compared case-insensitively). (`INVALID_ENUM_VALUE`)
- `name` must be in the [`codeName`](./value-formats.md#codename) format. (`INVALID_CODE_NAME_FORMAT`)
