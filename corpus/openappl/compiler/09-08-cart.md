# 9.8 Shopping cart

A service with `shoppingCartConfig.basicSettings.useShoppingCartFeature: true` gets a
shopping cart: a per-user (or per-guest) basket with server-side pricing, promotions,
optional stock reservation and a single-flight checkout that can create an order.

## Data objects

`<cart>` (default `cart`), `<cart>Item` (default `cartItem`), and `<cart>Campaign` when
dynamic promotions are on. Cart statuses: `active`, `churning`, `abandoned`,
`checkedOut`, `convertedToOrder`. An authored object of the same name is used as
declared, with missing fields added.

The live cart **MAY** be held in a fast store; the stored records are then a mirror and
**MUST NOT** be read for availability decisions.

## Routes

Under `/<cart>` on the service, each one switched by `apiSettings.enabledRoutes`:

| Route | Purpose |
|---|---|
| `GET /<cart>` | the current cart; `?checkoutId=<id\|latest>` returns a checkout outcome |
| `POST /<cart>/items`, `PUT /<cart>/items/:barcode`, `DELETE /<cart>/items/:barcode`, `DELETE /<cart>/items` | change lines |
| `POST /<cart>/recalculate` | reprice |
| `POST /<cart>/coupons`, `DELETE /<cart>/coupons/:code` | coupons |
| `POST /<cart>/redeemPoints` | loyalty points |
| `POST /<cart>/checkout` | checkout; the request body is the checkout data |

Typed refusals include **404** `CART_PRODUCT_NOT_FOUND`, **409** `CHECKOUT_IN_PROGRESS`,
**409** `CART_ALREADY_CHECKED_OUT`, **409** `CART_CAPACITY_EXCEEDED`, **502**
`ORDER_CREATION_FAILED`, **404** `COUPON_NOT_FOUND`.

## Rules

- The cart's owner is the logged-in user, else the guest session. Logging in does not
  adopt the guest cart.
- With a product catalogue bound, the server prices every line; prices sent by the
  client **MUST** be ignored. VAT rates are percentages on the wire.
- **Checkout is single-flight.** The first checkout claims the cart; every other checkout
  or change answers **409** `CHECKOUT_IN_PROGRESS` while the claim's lease is live. The
  client polls the outcome (`succeeded`, `partial`, `failed`, `inProgress`) and retries
  only a failed retryable outcome or an expired lease.
- **Reservation** (`reservationSettings.enabled`): adding a line holds capacity for a
  time; removing, clearing, expiry and a failed checkout release it; a successful checkout
  consumes it. The cart never writes stock columns itself.
- **Order creation** (`checkoutSettings.orderCreationMode`): `local` creates the order
  record in the same service and marks the cart `convertedToOrder`; `remote` publishes
  the checkout event for an order service to consume (a validator requires a consumer);
  `none` only freezes the cart.
- The cart never calls a payment provider; payment starts from the order
  ([9.4](09-04-payment.md)).

> **To verify:** whether stock reservation is available on every reference target
> (documented for the primary one).

## Events

The checkout event, default topic `<serviceCodename>-cart-checkout-completed` (or the
configured topic, scoped to the project), `type: <cart>.checkoutCompleted`, with
`data = { cartId, checkoutId, cart, items, rewards, orderId, orderCreationMode, checkoutData }`.
Mirror records publish ordinary data-change events.
